# 知识图谱本地混合检索与 AI 材料包

## 公共政策原文路径与迁移

仓库的 `data/public-policy/snapshot.json.gz` 仅包含八类公共图谱记录及原文清单，
`manifest.json` 固定压缩包和内容哈希、各表数量。75 个原文、提取文本、附件与目录
文件沿用仓库现有来源文件；导入时逐个核验哈希，并留存到目标库旁的 `policy-originals/`。
当前快照包含 37 条政策、1333 条条款；候选、待复核状态随数据保留。

正常启动应用时会自动校验并导入随项目提供的公共政策包，再同步规则和教学知识点，
教师、学生通过高校工作台的“政策与学习图谱”查看，无需手动执行导入命令。
首次导入前自动备份目标数据库；数据包或规则版本没有变化时直接跳过，不重复导入。
初始化失败会阻止应用开始服务并显示错误，不以缺少政策原文的空图谱冒充初始化成功。
这一流程不联网抓取、不调用 AI，也不会自动发布替换已有教学版本。

仅需单独维护指定数据库时，可先用应用初始化业务库，再执行以下维护命令：

```powershell
python scripts/import_public_policy.py --db <现有业务数据库文件>
```

导入前自动备份，只插入缺失的公共节点。相同 ID 的正文、来源或规则内容冲突时停止，
已有人工复核、课程、知识点、师生账号及作答均保留；不会用公共快照替换业务数据库。
重复导入和换目录后再导入均保留现有记录。公共数据包不含任何账号、企业材料或教学记录。

磁盘数据库新导入的 `Policy.raw_file_path`、`Clause.source_location` 中的
`retained_raw_path` / `retained_text_path` 使用相对于数据库所在目录的 POSIX 路径，
例如 `policy-originals/<sha256>.html`。读取不依赖启动服务时的工作目录；旧绝对路径
在显式迁移前仍兼容。原文留存目录须在数据库所在目录内，移动时一起复制数据库和
原文目录。内存工程测试库没有磁盘根目录，继续使用测试临时文件的绝对路径。

现有库先检查，再在服务已使用支持相对路径的代码后应用：

```powershell
python scripts/relativize_policy_paths.py --db <数据库文件>
python scripts/relativize_policy_paths.py --db <数据库文件> --apply
```

默认命令仅核验并回滚；`--apply` 先生成完整 SQLite 备份，再在事务内修改路径。
原件和提取文本必须通过哈希核验，普通条款字符范围须与原文一致；目录解释、清单
整理与目录中的原文快照按其字段和内容哈希核验，不冒充原文字符切片。文件缺失、
篡改、相对路径越界或定位不一致时不保存修改。

迁移保留节点 ID、关系、正文、内容指纹、版本、审核状态及时间戳，不重写已发布的
教学快照。仅物理留存位置变化不会触发教学依据版本更新；正文、来源哈希、原文
坐标或审核状态变化仍触发原有更新提示。此脚本不打包账号、企业数据，也不发布数据。

本轮根据《知识图谱本地混合检索与AI材料包_开发实施计划_v1.0》完成工程实现和本地验收，代码归属 `policy-knowledge-graph`。用户明确允许复用此前采集的数据并编纂测试数据，因此采用 20 份标记为虚构的政策场景建立独立工程预期集，另复用 5 份真实来源快照验证解析、检索和溯源。没有把合成预期集称为税务人员审核过的标准答案。

## 依赖与复现

在已安装项目依赖的 Python 环境中补装可选本地检索依赖：

```powershell
python -m pip install -r requirements-knowledge.txt
python scripts/prepare_kg_model.py
```

准备脚本是显式联网操作。模型默认保存在当前进程的 `%LOCALAPPDATA%/TaxPearls/models/bge-small-zh-v1.5-onnx`，可用 `TAXPEARLS_KG_MODEL_DIR` 指定其他目录。Codex 环境的 LOCALAPPDATA 可能被 Windows 应用包重定向，应以准备脚本输出为准。模型不进入 Git，不下载可执行模型代码；运行时逐项校验本地 manifest 中的哈希。

使用 [BAAI/bge-small-zh-v1.5](https://huggingface.co/BAAI/bge-small-zh-v1.5) 的 MIT 许可模型，固定上游修订 `7999e1d3359715c523056ef9478215996d62a620`，固定 [ONNX 导出](https://huggingface.co/onnx-community/bge-small-zh-v1.5-ONNX) 修订 `9507db33464b5da99a532ac26b2a251767cbc62b`。ONNX 及其外部权重有代码内固定 SHA-256；tokenizer、配置和上游说明的哈希写入本地 manifest。

以下命令在本工作区根运行；新建验收库拒绝覆盖已存在文件，已建库可直接重新索引/评测：

```powershell
python -m src.kg_retrieval.cli seed-demo --db output/kg-retrieval/tax_kg.db --originals output/kg-retrieval/originals --offline
python -m src.kg_retrieval.cli build-index --db output/kg-retrieval/tax_kg.db --output output/kg-retrieval/vectors --offline
python -m src.kg_retrieval.cli evaluate --db output/kg-retrieval/tax_kg.db --cases tests/fixtures/kg_retrieval/gold_cases.json --output output/kg-retrieval/retrieval_report.json --offline
python -m src.kg_retrieval.cli retrieve --db output/kg-retrieval/tax_kg.db --cases tests/fixtures/kg_retrieval/gold_cases.json --case K13 --output output/kg-retrieval/K13.json --offline
```

`import-corpus` 支持 `--manifest 来源清单.json --document-id 文档ID`（可重复）、`--db`、`--originals`、`--output`，复用此前原件及文本哈希。识别“第N条”和“一、”章节；无法可靠分条时保留“未分条正文”并标 needs_review。发文日期只取明确 publish_date，不把落款日期冒作发布日期。

数据库增加辅助 `kg_clause_fts`、FTS 触发器、`kg_clause_vectors`；八类领域表保持兼容。向量缓存随条款内容及版本增量更新，FAISS 导出文件名带索引哈希，映射 JSON 记录模型、条款、分块、内容与索引文件校验值。索引导出不替代 SQLite 持久映射。

新增接口：GET `/api/knowledge/checks`、GET `/api/knowledge/retrieval/status`、POST `/api/knowledge/retrieve`。企业模式只接受 task_id、expected_revision、项目/地区/主题等控制参数，事实从当前授权任务读取。客户端不能在此接口提交任意企业金额。保存前再次鉴权及比较版本；资料变化时仅将实际依赖指标变化的旧检查标记 stale，重新检索时按完整内容决定是否复用。旧版本保留。

AI 门槛读取当前工作区 `output/kg-retrieval/retrieval_report.json`，核对全部案例、门槛指标、实现指纹和包内模型指纹。检索、适用核查或材料包代码改变后须重新离线评测。AI 使用现有 knowledge 用途配置及密钥优先级；本轮只在进程中读取原项目 `.env` 的 AI 项，不复制密钥文件或把密钥写入产物。

### 模型容量与分类批次（2026-10-18）

企业自动检查不再传入固定的 6000 预算。服务按当前用途选择的凭证与模型，从 `/models` 保存 `context_window`、`max_output_tokens`；上游没有容量声明时，明确标记保守回退，不能将模型名称猜作 1M 容量。默认单批输入目标为 128000 的保守 Token 上界估算，并限制在模型窗口的 60% 以内；另行扣除实际输出额度（默认 8192）、8192 指令额度与至少 4096 / 窗口 5% 的安全余量，取其中更小者。估算采用实际 JSON 序列化后的 UTF-8 字节上界，不是真实分词或账单用量。

模型容量为硬上限，128K 是本系统面向当前核查材料规模的工程默认值，不是厂商统一推荐值。缓存命中输入仍完整计入输入预算；缓存仅影响重复计算与费用。固定指令和同项核查公共信息放在可变材料之前以利前缀缓存，不假设上游必然命中。容量字段与输入/输出含义见 [DeepSeek 模型接口](https://api-docs.deepseek.com/api/list-models/)、[Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/) 与[上下文缓存](https://api-docs.deepseek.com/guides/kv_cache/)。

超过单批目标时按资料类型、政策文件、例外/排除依据、变更依据和待核实事项组织批次。保留完整原文；超长条款使用带原始文本 SHA-256、条款 ID、字符位置和片段序号的无损拆分。每批明确关联本项必要条款 ID，无法在单批看到全部依据时只允许辅助待核查说明，不能将局部分析升级为整体通过或正式结论。引用和金额仅按该批实际发送的条款及事实校验。

每批请求前重新检查权限与任务版本。已完成且校验通过的批次随任务加密保存；某批失败后停止继续发送，页面提示重新开始时复用已完成批次。复用绑定材料内容、批次内容、模型/接口、思考配置、输出额度、分析指令及校验版本；变更配置不能误用旧模型结果。未完整输出的响应不作为完成批次缓存，失败请求是否计费仍以服务商为准。上游实际输入、缓存命中/未命中、输出用量分别保留，不以预算代替账单。

## 上传、核查与报告衔接补充验收（2026-10-15）

两个结果分别输出并在网页、HTML/PDF、完整 JSON 中保存：

| 结果 | 行为 |
| --- | --- |

对候选 VAT-R01，即使已确认存在差额，风险仍待核查；差额为零仅表示本项数值比较没有差异，不代表整户全面合规。无法比较时不输出伪差额。发票或申报原件、覆盖、所属期或适用表单改变后，原口径确认失效；页面不自动将旧确认填成当前确认，受影响项目需重检。无关科目余额补传不使该项口径确认失效。

发票按实际明细金额汇总：明确红字负数参与冲减，作废排除，同一明确票号及明细行重复只计一次，不同明细行保留；没有明细行号且同票存在冲突时仍待核实。票号去重同时绑定购销主体和方向。跨月原件保留，但不计入本期；未知红字/作废状态、符号矛盾、未解析来源或字段缺口不能静默排除后声称完整合计。当前只支持已识别结构和明确的红字负数，不自动判断真实业务中的纳税义务时点及所有调整事项。

缺发票不等于零。只有本任务明确绑定的空明细原件、可识别空表结构、完整一致的企业/期间/元单位元数据、无其他记录或解析缺口，并经人工确认零发生额，才取得零值；报告保存证明文件及哈希。纯空集合、无法解析文件或勾选本身均不构成零发生额证据。

补充边界验证包括：另一个未解析发票原件，以及同一工作簿中「一张可识别空表 + 另一张未识别非空表」，二者均保持未知，不能被空表证明掩盖。

### 真实 AI、外送与报告
