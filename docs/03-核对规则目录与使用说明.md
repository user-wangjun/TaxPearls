## 直接运行

在项目根目录执行：

```powershell
.venv/Scripts/python.exe -X utf8 scripts/check_rules.py
.venv/Scripts/python.exe -X utf8 -m unittest discover -s tests -v
.venv/Scripts/python.exe -X utf8 main.py -i "你的审计材料.xlsx"
```

第一条命令读取 `samples/规则核对样例.yaml`，实际执行规则，比较人工给定的状态和测算值，输出 `output/规则核对结果.json`。不一致返回退出码 1，样例结构或路径错误返回非零退出码。结果文件保留公式、原始指标及来源、适用范围、阈值依据和未执行原因。

样例按每条规则独立组织，不能把不同规则的独立底稿当成同一家企业的完整账套。每组 `baseline` 是正常值，`set` 覆盖指定值，`remove` 删除指定证据。每条规则均有正常、命中、恰好边界、缺证据四例，共 96 例；测算期望独立手工编写，不由引擎生成答案。

## 如何给规则提供数据

原来的三张必需表继续使用；新增一张**可选**工作表 `补充指标`，表头严格为：

| 指标 | 数值 | 来源 | 所属期 | 口径说明 |
| --- | ---: | --- | --- | --- |
| 人力.个税申报人数 | 110 | 仿真个税申报明细第1页人数汇总 | 2026-06 | 工资薪金、同一月份、按人员去重；全部仿真 |
| 人力.社保参保人数 | 100 | 仿真社保参保明细第1页人数汇总 | 2026-06 | 同一主体、同一月份、按人员去重；全部仿真 |

上述两行恰好偏离 10%，R-004 通过；将 110 改为 111 则命中。企业信息的所属期也必须为 `2026-06`。该表仍是人工整理的标准指标入口，**不是社保系统自动接入**。P1 另支持统一模板的 `利润表`、`资产负债表`、`现金流量表`、`历史指标`、`发票明细` 和 `银行流水`；发票支持下节列出的确定来源 XML / Excel 映射，银行支持建设银行公开字段口径和通用收支表头。其他账表不声称兼容所有财务软件原始格式。

### 发票来源适配与规则口径

- XML 仅接受财政部电子凭证会计数据标准的数电发票 XBRL 实例；读取票号、开票日期、不含税金额、税额、价税合计、红字标志、会计主体、用途确认、确认所属期及进项转出。解析结果不代表已验真或已验证数字签名。
- 来源 Excel 允许发票号码、数电票号码等同义表头；发票方向可由显式方向、销项/进项工作表名或企业与销购方税号唯一判定。判定不唯一时拒绝，不按文件名猜测。
- 红字发票冲减、作废发票剔除；价税合计与不含税金额加税额须在 0.01 元内勾稽。同表或跨文件重复票号、跨审计期间开票日期均拒绝。
- R-016 使用 `发票.销项净额`，仍须另补未开票申报额和其他调节；开票额不能替代全部申报销售额。
- R-017 使用 `凭证.本期确认抵扣税额`，只汇总已明确确认抵扣且确认期落在审计期内的采购税额，并扣减明确进项转出；`发票.采购税额净额`只是全部采购有效票税额净额，不能直接替代抵扣额。
- R-019 使用采购/销项不含税净额。零税额必须显式填 0；缺失税额、无法识别状态、正常票负数或价税不勾稽均拒绝。

### 银行来源适配与 R-015 调节口径

- 来源 Excel 支持建设银行公开企业账户明细中的唯一编号、交易日期、借/贷方发生额、余额、对方户名/账号和摘要，也接受交易流水号、收入/支出双列或“单金额 + 收支方向”同义表头。当前自动口径只接受人民币；不宣称兼容未实测的银行版本。
- 原始流水按唯一编号跨文件去重并校验交易日期落在核对期；只生成收入/支出流水合计。完整账号不进入持久化证据，界面明确提示原始入账不等于收入。
- `银行调节`必须逐笔覆盖所有收入流水：经营回款可填写经发票/合同核对的不含税收入；借款、内部转账、资本金、往来、预收等必须显式填 0。现金、应收、跨期和退款折让通过独立加减项记录。
- 每条调节必须填写权责所属期、底稿编号、说明并标记已复核；未分类、重复分类、未复核、错误引用和非经营款误认收入均拒绝，不用“自动猜分类”换取表面通过。
- R-015 只读取 `银行.调节后不含税收入 = 银行.经营回款已复核不含税额 + 银行.权责口径调节额`，与账面营业收入比较；`银行.收入流水合计`永远不能替代该指标。

### 多期间自动归集

`历史指标`沿用五列表头 `指标 / 数值 / 来源 / 所属期 / 口径说明`，有两种兼容输入：

- 原有成品指标：`历史.*` 或 `年度.*`，按原逻辑直接进入规则引擎。
- 标准期间序列：支持 `利润表.营业收入`、`利润表.营业成本`、`利润表.净利润`、`资产负债表.资产总计`。系统按企业核对所属期自动生成 `趋势.<指标>.本期/上期/上年同期/环比率/同比率/滚动12月`，并生成 R-020、R-022、R-024 使用的兼容指标。

期间可写完整自然月、季度、半年或年度，例如 `2026-01`、`2026Q1`、`2026H1`、`2026`，也支持对应的完整起止日。等价期间标签视为同一期，重复值会被拒绝。本期报表与历史序列可以放在同一 Excel，也可以分文件上传后合并；同一指标、同一期间出现冲突值时拒绝审计。

发生额只在最近 12 个自然月全部存在时生成滚动12月，缺一个月也不会用 11 个月冒充。资产总计属于期末余额，只做期点比较，不跨月相加。基期为 0 会保留真实的上期/上年同期值，但不生成无定义的环比率或同比率；依赖零基数的规则保持未执行并给出原因。

填表约束：

- 指标名逐字对应 YAML 的 `inputs`。账面基础指标与原增值税申报指标仍从原表读取，补充表禁止覆盖它们。
- 金额统一为人民币元，比率用小数（13% 填 0.13），人数为非负整数。加权税率是税率小数。正负号按各项口径说明填写。
- 补充值必须带可定位的文件/表/栏次/底稿来源和口径说明。来源缺失、期间不一致、重复指标、非数字、NaN、Infinity、公式文本均报输入错误。
- `所属期` 是本次核对期，须与企业信息完全一致；历史实际起止日、报告日写在口径说明中。引擎不会从自由文本推断同比期间或验证官方行业身份，提供者需按规则 scope 核实。
- 未填的值保持缺失；依赖规则显示 skipped。明确的 0 才参与运算。无缓存或其他 Excel 公式不自动求值，请提交已核实的数值。
- 多科目聚合必须完整：收入需要 6001 和 6051，成本需要 6401 和 6402；无发生额也提供零行。原始科目是本期发生额，不应含损益结转等非业务发生额。财务软件若混入结转或使用其他编码，应先按口径整理。
- 行业/地区参考值不提供默认兜底。R-003、R-021 需显式填入上下限，在来源和口径中注明地区、行业、适用期、纳税人类型和发布者；仿真区间必须标记示意。

## YAML 契约与判定语义

保留三种基本求值类型：

| 类型 | 判定 |
| --- | --- |
| deviation | 差额 / 正基数；默认取绝对值，严格大于 threshold 才命中 |
| amount_mismatch | 差额；默认取绝对值，严格大于 tolerance 才命中 |
| ratio_range | numerator / 正 denominator 不在闭区间 [min,max] 时命中 |
| all（条件组合） | 每个子条件同时命中；不是第四种业务分类，也不是图查询 |

`direction` 仅用于前两种类型：absolute=绝对差，above=left−right，below=right−left。`all` 不短路，任何必需证据缺失都会 skipped，避免缺数据被其他条件掩盖；组合规则没有单一单位的 measured，结果为 null，计算过程逐项展示。

操作数可以是指标名、有限数值，或白名单公式 `add/sub/mul/div/min/max`。sub/div 恰好两个操作数，其余至少两个；div 分母必须正。不执行 Python、eval、SQL 或任意代码。ratio_range 的 min/max 可引用带来源的指标。

加载时校验：ID 唯一、三类业务枚举、severity、字段类型、公式、非负阈值、区间、重复 YAML 键；公式依赖、inputs、evidence 三者必须一致。新增必填元数据：inputs、scope、threshold_basis、references、version。旧的自定义九字段 YAML 需补齐这些内容，不能再省略证据口径。

金额与比例运算采用 Decimal；严格边界等值不命中。相对偏离或比率分母为零/负数时返回 skipped，而不是 Infinity 或默认零。零/零也未执行；需要核对零收入时可单独使用绝对差额规则。

每条证据卡显示原始指标来源及明细、完整公式、阈值出处、适用范围、规则版本和官方法条链接。命中是待人工复核的预警，pass 仅表示未触发当前规则；重复关联预警不能当作独立风险金额相加。

## 逐条口径

### R-001 账面收入与增值税销售额差异

- 判定：营业收入 − 增值税.销售额 的绝对值 / 增值税.销售额 > 0.1。
- 适用范围：同一主体、同期累计、不含税；仅筛查差异，收入确认时点、视同销售、免税和非应税项目须人工调节。
- 阈值：相对偏离超过10%为教学预警参数，并非法定阈值；等于阈值不命中。
- 取数：该 YAML 的 `inputs` 列出全部指标及来源；没有业务发生也应显式填 0，不能留空。

### R-002 一般计税应纳税额账申勾稽

- 判定：max(0, (账面.销项税额 − max(0, ((账面.进项税额 + 增值税.期初留抵税额 + 账面.抵扣调整) − 账面.进项转出)))) − 增值税.一般计税应纳税额 的绝对值 > 100。
- 适用范围：仅一般计税、减征和预缴前税额；抵扣调整必须已核实，不能用销项减进项直接代表全部应纳税额。
- 阈值：金额差额容差100元为本项目示意核对参数，不是税法规定的重要性标准；等于容差不命中。
- 取数：该 YAML 的 `inputs` 列出全部指标及来源；没有业务发生也应显式填 0，不能留空。

### R-003 增值税税负率偏离参考区间

- 判定：增值税.应纳税额 / 增值税.销售额 不在 [参考.税负率下限, 参考.税负率上限]。
- 适用范围：销售额为正；参考值必须与本企业地区、行业、纳税人身份、期间及分子定义一致。没有可靠基准则不执行。
- 阈值：上下限由补充指标显式提供并保留出处；样例1%—4.5%仅为仿真示意，非法定税负标准。
- 取数：该 YAML 的 `inputs` 列出全部指标及来源；没有业务发生也应显式填 0，不能留空。

### R-004 个税申报人数与社保人数差异

- 判定：人力.个税申报人数 − 人力.社保参保人数 的绝对值 / 人力.社保参保人数 > 0.1。
- 适用范围：同一月份去重人数；入离职、退休返聘、劳务派遣、缴费时点均可导致合理差异，不能据此直接认定虚列工资。
- 阈值：相对偏离超过10%为教学预警参数，并非法定阈值；等于阈值不命中。
- 取数：该 YAML 的 `inputs` 列出全部指标及来源；没有业务发生也应显式填 0，不能留空。

### R-005 销项税额账申差异

- 判定：账面.销项税额 − 增值税.销项税额 的绝对值 > 100。
- 适用范围：同一期一般计税销项；红字调整与纳税义务发生时间须核对。
- 阈值：金额差额容差100元为本项目示意核对参数，不是税法规定的重要性标准；等于容差不命中。
- 取数：该 YAML 的 `inputs` 列出全部指标及来源；没有业务发生也应显式填 0，不能留空。

### R-006 进项税额账申差异

- 判定：账面.进项税额 − 增值税.进项税额 的绝对值 > 100。
- 适用范围：账面确认与申报抵扣可能跨期；本规则仅筛查差异，不能据此认定多抵进项。
