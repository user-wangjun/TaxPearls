## 文件与使用方式

- `真实案例数据总表.xlsx`：一张索引、六张企业专页。原始数值与原单位保留，标准金额用公式换算为元，逐行记录原文位置、指标映射、异常标记。公式已计算并保存缓存。
- 六个企业子目录：分别包含官网原始 PDF/HTML 与 `公开数据.json`。JSON 是这次材料交付的机器可读格式，不是现有 loader 支持的输入格式。
- `来源附件/四案处理结果.html`：税务总局对春风船舶、星印网络、慧业医药等案件的处理结果通报，用于与对应案情报道交叉核对。两者同为税务部门披露，不构成独立第三方调查。
- `来源清单.json`：下载地址、最终地址、文件大小、原始文件 SHA256、获取日期；另保留一条未入选北交所材料的下载失败记录，不作为证据。
- `核验数据.py`、`核验结果.json`：可复现的数据与文件核验，以及执行时的业务代码快照状态。

先看 Excel 索引确定要测的能力，再打开企业专页；按“原文定位”回查同目录官网原件。程序测试使用 JSON 中的字段和空值语义。**不要把总表重命名为审计材料后直接导入。**

## 预期结果与异常处理

- **嘉元收入对照**：按检索开始时R-001的绝对偏离度公式及10%阈值，三年均不到阈值。已独立复算，不等于项目引擎执行通过，也不证明全部税务合规。销项和进项来自申报披露，不能又当账面值去“证明”R-002通过。
- **嘉元源文冲突**：第87页表格写82.32万元，正文写82.23万元；正文又将632.52写成“元”，第86页表格为“万元”。两种记载均保留。收入主表差额与主表两数可勾稽，但跨期分解应复核。
- **唯都延迟申报**：保留2019/2020年末暂估数据和后续整改证据。年末余额不能当全年营业收入，两个年末存量不可累加。现场检查口径与披露测算口径不能混为同一个字段。
- **春风人数**：61−36=25人，仅证明公开的个税申报人数与实际用工不同。R-004需要的社保人数缺失，预期应为未执行。不能为了命中规则把36映射成社保人数。
- **星印收入**：2469.63−612.76=1856.87万元。查实收入属于外部调查结果，不能当账面收入来强行触发R-001。适用于未来外部收入交叉规则；关联关系已放入JSON的`relations`。
- **慧业研发**：原文80%以上保留下限语义；100%与80%是委托研发费用计入基数比例。没有依据将所有违规金额相加，也不倒推未公开合同金额。
- **隆旭文书冲突**：第一部分（一）富顺康173份发票对应金额、税额及号码与（二）不一致。分项批次可复算20+173+70=263份，税额合计4,437,123.02元，但这是源内勾稽，不能替代主管机关更正。最终罚款采用决定最终数，不能将文中50万元处罚讨论再叠加。此组特别适合FR-A03数据质量测试。

检索开始时R-003使用商贸行业演示区间，不能据此给制造业贴税负正常标签。历史案例的适用法规须以案期为准，不能把2026年增值税法追溯套用到所有历史事实。本包不生成法律意见或真实审计结论。
