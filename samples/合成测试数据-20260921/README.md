# 税海拾珠合成测试数据

2026-09-21，经用户授权人工编写。**16 套独立 Excel，全部明确标注合成，不对应真实企业、税号或申报记录。** 面向当前 `loader.py` / `config.py` 的标准化导入格式及 R-001～R-024。

已验证：14 套可导入，2 套按设计拒绝；14 × 24 = **336 项规则判定全部符合事先设定的预期**。全部 24 条规则均有命中和通过样例，正常对照 24 项通过。详见 `核验结果.json`。

## 直接使用

在项目上传入口可以多选本目录的 `.xlsx`，选择“每个文件分别审计”，即可整批导入；这些样例代表不同企业，不应合并为一户。也可以单独选一份。建议先试 **01 正常对照**，再试 **02 收入少申报**，最后试 **13 缺项**与 **15 重复科目**，依次观察通过、预警、未执行和输入错误。

每份工作簿有六张表：

| 工作表 | 内容及用途 |
| --- | --- |
| 企业信息 | 必填四字段；附合成声明、场景、期间、余额方向及简化假设 |
| 科目余额表 | 当前程序要求的六列；通常24个唯一科目，含6001、6051、6401、6402和进销项科目 |
| 增值税申报 | 当前程序要求的五项核心数值，另附期初留抵与一般计税应纳税额 |
| 补充指标 | 按项目五列格式提供报表、外部交叉、历史及测试参考值；来源逐项定位到本工作簿单元格 |
| 模拟业务底稿 | 报表及业务汇总、实际期间、单位与口径，包含银行收入调节依据 |
| 模拟凭证 | 本期复式记账明细，可核验余额表发生额；零业务样例只有表头 |

前四张表供当前程序读取，后两张用于人工追溯。本包采用项目现有的“补充指标人工整理”入口；发票、银行和薪酬材料为模拟汇总底稿，未制作电子税务局 XML 或银行原版导出文件，也不用于验证尚未实现的原始格式适配器。

## 数据口径

- 当前核对期统一为 **2026年8月**。上年同期指标为2025年8月；年度序列为最近三个已结束的完整年度2023、2024、2025，其中“年度.本年”锚定2025。每条历史值在底稿与口径说明中标明实际期间，不把全年数用作上年同月数。
- 金额为人民币元、数值型；科目编码和模拟税号为文本。借方余额为正、贷方余额为负。损益已结转，不能用期末余额替代收入或成本发生额。
- 商品税率13%、所得税费用按正利润25%计算、税负参考1%～4.5%、毛利参考10%～50%均为本包的**测试假设**。不代表具体企业适用税率、官方预警标准或真实行业分布。
- 账簿先由平衡的模拟凭证汇总，再在指定申报或底稿中植入差异。第15套故意重复行；第13套故意删去零发生额科目和留空指标。其他科目余额表保持期初、本期发生额、期末借贷平衡，且与模拟凭证相符。
- 输入全部保存为固定数值快照，无Excel公式。当前导入器不接收金额公式；改动底稿或凭证后须同步重算导入表，并重新确认预期。当前程序不会自动读取后两张表来重建前四张。
- 工作簿包含场景说明，适用于开发、教师演示与对照测试；未做隐藏答案的学生盲测版。

## 验证与复现

在项目根目录运行：

```powershell
.\.venv\Scripts\python.exe 'samples\合成测试数据-20260921\核验数据.py'
```

- `预期结果.json`：预先手工指定的每套24条状态、代表性计算值及预期输入错误；没有从程序实际输出反填预期。
- `核验数据.py`：检查凭证借贷平衡、余额滚动、凭证与科目发生额、补充指标单元格来源、合成标记与格式；调用现有文件/内存导入、规则引擎及HTML报告生成。
- `核验结果.json`：实际逐套状态、计算过程、未执行理由、文件SHA256与业务代码/规则SHA256。最后一次核验失败数为0，336项规则结果符合预期。

已完成工作簿渲染检查。本轮验证范围是 **Excel → 文件及内存导入 → 规则 → HTML报告**；未验证浏览器交互、Web HTTP上传接口或PDF导出。合成集用于功能验证，不能作为真实企业识别准确率的证据。业务代码及规则未因本次数据编写而修改。
