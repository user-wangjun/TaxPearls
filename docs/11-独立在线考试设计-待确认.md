## 0. 一句话结论

现有"作业/组卷"体系**无法承载在线考试**（每题必须挂一个仿真审计案例、判分口径是"勾选命中的风险规则"、没有限时与防作弊），
所以考试要**独立建一套表与接口**，与作业体系并行、互不写对方的数据；只在身份/名册、冻结快照、CSV 渲染、前端挂载这几处复用既有资产。

## 2. 范围

### 2.1 v1 做

1. **考试卷**：教师建卷（标题/说明/时长/作答窗口/每题分值/及格线/是否乱序）、加客观题（单选、多选）、保存草稿、发布（发布即冻结题目快照）。
2. **考生名单**：支持"按教学班整班导入"与"手工指定名单"两种；名单以 `users.id` 为准。
3. **学生机考**：进入考试 → 服务端开一场会话（记 `started_at` / `ends_at`）→ 取卷（**不含答案与解析**）→ 逐题保存 → 交卷 / 到点系统自动收卷。
4. **限时**：剩余时间一律**服务端计算**下发；到点后所有写接口 409，并惰性收卷（无需后台定时任务）。
5. **防作弊（只做记录与告知）**：切页/失焦、复制/粘贴/右键计数、心跳、同账号并发会话互斥、IP/UA 记录；监考台给出"异常次数"，**由教师判断，系统不自动判作弊**。
6. **判分与成绩**：客观题自动判（集合完全一致得满分，与初级会计客观题口径一致）；总分/及格判定；教师可复核单题；**成绩默认教师手动发布**才对学生可见；成绩单 CSV 导出。
7. **监考台**：考生列表（状态、剩余时间、已答数、异常次数）、强制收卷、提前结束考试。

### 2.2 v1 明确不做（写进文档避免误读）

- 主观题/填空/分录题（v1 只客观题；主观题留 v2，届时也只做人工评分，不做 AI 阅卷——全库确认无 AI 判分实现）
- 摄像头/录屏/人脸识别/屏幕锁定/强制全屏（浏览器侧不可靠，不做"看起来做了其实能绕"的东西）
- 自动判定作弊并作废成绩
- 试题随机抽题（每人不同卷）→ v1 只做**题目顺序乱序**与**选项乱序**（可选开关），同一份卷
- 考试成绩并入 `classroom.gradebook` / 学情统计 / FR-U05 报表（v1 三者口径保持不变，避免混口径对不上账；v2 再议）
- 考试成绩自动进错题本（`mistake_book`，作业线在 `storage.py:1674` 捕获；v1 考试不进，留开关）

## 4. 数据模型（新表 6 张，全部 additive，不动既有表）

> 迁移纪律：与 `training_task_settings` / `course.term_id` 同样做法——`CREATE TABLE IF NOT EXISTS` + `PRAGMA table_info` 加列；
> **新模块的迁移在 `webapp/app.py` 的 register 序列里登记前，先确认它依赖的表已建**（我在 `teaching_case_tasks` 上踩过"注册太早被静默跳过、首次建库漏表"的坑）。

**E1 已落地（2026-10-23，commit 待定）**，落地时相对设计稿有三处改动，记在这里以免设计与代码脱节：

1. 表名统一为 `online_exam_*`（`online_exam_paper` / `_question` / `_roster` / `_session` / `_answer` / `_event`）。
   原因：库里已有 `exam_date`（`schema.py:356`）是**外部考证的考试日期**（官方/预计/个人计划），
   与"在线机考"不是一回事，同名前缀将来容易误读。
2. 教师侧外键指向 `college_user(id)` 而不是 `users(id)`——教师会话的身份就是 college_user；
   只有学生名单与场次指向 `users(id)`（学生用学号登录平台账号才能进考试）。
   首次迁移曾写反并被 SQLite FK 拦住，已用"空表重建"修正（见 `exams._recreate_if_stale`）。
3. `scheduled/open/ended` 不做落库状态，改成**派生 phase**（见 §5.1），省掉定时任务。

### 4.2 `online_exam_question`（卷内题目**快照**）

`id, paper_id, position, kind(single|multiple), stem, options_json, answer_keys_json, points, explanation, source(manual|bank|ai), source_question_id, fingerprint, UNIQUE(paper_id,position)`

## 5. 状态机

### 5.1 考试场次 `online_exam_paper.status` + 派生 `phase`

**落地时改成"落库状态 + 派生阶段"**：状态只存 `draft / published / closed / archived`，
`scheduled / open / ended` 由 `open_at / close_at` 与当前时间算出来（`exams._phase`），
不落库——否则没有定时任务，状态到了点不会自己变，只能靠人点。

```
status（落库）: draft ──publish──> published ──close/close()──> closed
                任意状态 ──archive──> archived（软删，不删学生记录，与作业线归档同口径）

phase（派生）:  draft | scheduled（未到 open_at）| open（窗口内）
                | ended（过 close_at）| closed（已结束）| archived
```

`graded / released` 不单列状态：判分结果落在 `online_exam_session.score`，
发布用 `released_at / released_by` 表达（E3）。

### 5.2 考生会话 `online_exam_session.status`（E2）_session.status`

```
not_started（在名单内、未进入；E1 还没有会话行，以 roster 表示）
   └─start(窗口内)──> in_progress（ends_at = started_at + duration，且不超过 close_at）
        ├─submit────────> submitted（正常交卷）
        ├─到 ends_at────> forced（系统按已答内容收卷，惰性触发）
        ├─教师强制收卷──> forced
        └─窗口结束未进入─> absent
迟到（超过 open_at+late_entry_minutes）→ 不允许进入，保持 not_started
```

**惰性收卷**：部署是单进程 uvicorn、无定时任务，所以在 `取卷 / 保存答案 / 交卷 / 监考台查询` 四个入口统一调用 `ensure_closed()`，把超时仍 `in_progress` 的会话置 `forced`。**剩余秒数一律由服务端算**，前端倒计时只是展示。

## 6. 限时与防作弊（只做服务端能验证的）

| 能力 | 做法 | 诚实边界 |
|---|---|---|
| 计时 | 服务端 `ends_at`；接口每次返回 `remaining_seconds` | 前端改表没用，提交时服务端再审 |
| 到点收卷 | 惰性收卷（见 §5.2），到点后写接口 409 | 不做后台定时任务 |
| 切页/失焦 | 前端 `visibilitychange` / `blur` 上报事件，累计 `violations` | 只记录，可关、可误报，**不自动判作弊** |
| 复制/粘贴/右键 | 禁用并计数 | 可被开发者工具绕过，只作提示 |
| 心跳 | 每 30s 上报，记 `last_heartbeat_at`；监考台显示"长时间无心跳" | 用于发现掉线，不等于作弊 |
| 并发会话 | 同 `paper_id+student_id` 只允许一场 in_progress，第二处进入 409 | 不做"挤下线"（避免误伤掉线重连） |
| 环境记录 | 记录 IP / UA / 首末活跃时间 | 不做设备指纹、不做 IP 封禁 |
| 断线续答 | 逐题保存 + 重入恢复（同会话继续，不重置计时） | 计时不暂停（重连窗口由教师判断） |

## 7. 判分与成绩

- **客观题**：沿用既有口径"选择集合与标准答案完全一致得满分，多选/错选/漏选均不得分"（`training_portal.py:2954-2968`，与初级会计客观题一致）；每题 `points` 可配，总分 = ∑得分，上限 100。
- **复核**：教师可对单题改分（`manual_score` + `manual_by` + `manual_note`），自动分 `points_gained` **保留不动**（与作业线"客观记录不被人工改写"同口径）。
- **发布**：默认 `answer_release='manual'`，教师点"发布成绩"后学生才可见分数、正确答案与解析。
- **成绩单**：新写聚合（考生 × 题 × 得分 + 总分 + 及格判定 + 用时 + 异常次数），CSV 复用 `gradebook_csv` 的 BOM 与注释行写法（Excel 直开）。
- **不并入**：学情统计、`classroom.gradebook`、FR-U05 报表（v1 保持三者口径不变，避免考试分数混进作业口径）。

## 12. 依赖与风险

1. **题库 0 题是硬前置**：真库 `training_bank_question`=0、`teaching_ai_task_question`=0。所以 **D4 的"教师手工出题"必须做**，否则考试无法在真库跑通。
2. **并发写**：20+ 人同时逐题保存 → 每次写走 `BEGIN IMMEDIATE` 短事务；建议前端"切题即存 + 30s 兜底批量存"，避免高频单行写。
3. **无后台任务**：所有"到点收卷"靠惰性触发（§5.2），监考台打开即刷新一次状态。
4. **时钟与剩余时间**：一律服务端计算下发，前端只展示。
5. **身份不对称**：名单以 `users.id` 为准；按学号导入时，找不到 `university_identity_links` 的行要显式列出（真库已有 1 例：学生账号存在但无 link）。
6. **口径隔离**：v1 考试成绩不进作业口径的统计/报表，避免"提交率、均分"混算。
7. **防作弊期望管理**：文档与界面都要写明"仅记录与提示，不做自动判定"，不夸大。
