## 一、产品概述

### 1.1 一句话定位

> 面向财税职业院校与代理记账机构的**可解释税务风险识别引擎**——一套内核，两个出口。

「可解释」是定语，不是形容词：每一条风险结论都必须能展开为「两个原始数值 + 计算过程 + 触发阈值 + 法条依据 + 建议动作」。做不到这一点的功能，不在本产品范围内。

### 1.2 要解决的问题

| 对象 | 真实痛点 | 现状做法 | 本产品的解法 |
| --- | --- | --- | --- |
| 财税专业教师 | 风险审计课无真实案例可讲，只能用教科书例题 | 手工编案例，无标准答案 | 由规则库反向生成带标注题库，题题有据 |
| 财税专业学生 | 只会背条文，不会查账；实习才第一次见真账 | 靠实习碰运气 | 沙箱内做仿真账套审计，自动评分 + 漏检/误报明细 |
| 代账机构会计 | 单人管 30+ 户，风险排查靠经验、靠抽查 | Excel 手工比对，覆盖不全 | 批量导入材料，分钟级出风险清单 + 证据卡 |
| 代账机构负责人 | 质量问题无法量化，出事了才知道 | 事后补救 | 风险留痕 + 复核轨迹，把质量变成可管理的指标 |

### 1.3 产品目标

按期次拆解，每期只承诺一件事：

| 期次 | 产品目标（一句话） | 达成标志 |
| --- | --- | --- |
| **P0** | 证明「一条规则怎么判、怎么举证」 | 上传一张 Excel，页面上看到完整证据链 |
| **P1** | 证明「一次完整审计怎么做完」 | 20–30 条规则跑完，出报告，学生能答题打分 |
| **P2** | 证明「五大能力全貌成立」 | 多源接入 + 关联方图分析 + 出题器 + 多租户 |

### 1.4 边界：明确不做的事

边界越清楚，越有说服力。以下四条为**硬边界**，不在任何期次的范围内：

| # | 不做 | 理由 |
| --- | --- | --- |
| 1 | 自动决定企业直销或收费模式 | 企业自用功能与商业渠道分开规划 |
| 2 | 面向税务机关的监管侧产品 | 与「服务小微企业」定位冲突，政务采购不可触达 |
| 3 | 自训模型、承诺准确率数字 | 不可举证，审计场景容错率为零 |
| 4 | 对接真实税务系统（生产环境） | 合规风险与实施成本双高；RPA 仅在沙箱内模拟 |

> **对「准确率」的正式口径**：不承诺准确率数字。对外统一表述为——
> 「内置 N 条可溯源风险规则，每条给出触发明细与法条依据，支持人工复核。」
> 前者一碰即碎，后者越问越硬。

### 1.5 成功度量

**P0 度量（唯一）**

- [ ] 给一张符合模板的 Excel 审计材料，在 Web 页面上（非命令行）能看到至少 1 条风险的完整证据卡
- [ ] 证据卡上的每个数值都能追到「哪个科目编码 / 哪张申报表哪一栏」
- [ ] 材料不足时，该规则显示「未执行 + 原因」，**不得**静默显示为「通过」

**P1 度量**

- [x] 规则库 ≥ 20 条，三大比对类型（内部勾稽 / 外部交叉 / 指标偏离）全覆盖
- [x] 一次完整审计从上传到出 PDF 报告 ≤ 5 分钟（单户、单期；本机自动化回归）
- [ ] 学生作业自动评分与教师人工评分的一致率 ≥ 90%（同批样本实测）

**P2 度量**

- [ ] 发票、银行流水、社保三类外部数据可接入并参与规则求值
- [ ] 关联方图规则可命中「同一实控人控制的多家企业间异常交易」类风险
- [ ] 出题器可由 1 条规则反向生成 1 套带标准答案的题目

## 二、用户与角色

### 2.1 目标用户

| 市场 | 角色定位 | 说明 |
| --- | --- | --- |
| **财税职业院校** | **主线** | 教师组织税务审计实训，学生通过仿真材料练习查账、风险识别与证据复核 |

## 三、产品架构与核心概念

### 3.1 一套内核，两个出口

```
        ┌──────────────────────────────────────────────┐
        │      可解释税务风险引擎（唯一内核）             │
        │  ┌──────────────┐   ┌──────────────┐         │
        │  │   识别层       │   │   解读层      │         │
        │  │  确定性规则引擎 │   │   LLM         │         │
        │  │  （可举证）     │   │  （可读性）     │         │
        │  └──────────────┘   └──────────────┘         │
        └──────────────────────────────────────────────┘
                     │                    │
          ┌──────────┴─────────┐   ┌──────┴───────────┐
          │   院校实训沙箱       │   │   代账作业台       │
          │ 出题 → 查账 → 评分   │   │ 导入 → 排查 → 报告  │
          └────────────────────┘   └──────────────────┘
```

### 3.2 识别与解读分离（核心技术原则）

| 层 | 技术 | 职责 | 硬约束 |
| --- | --- | --- | --- |
| **识别层** | 确定性规则引擎（YAML 声明 + 求值） | 判定是否命中风险，产出数值与证据 | **绝不用 LLM 做风险判断。** 审计场景容错率为零，LLM 幻觉无法举证 |
| **解读层** | LLM | ① 把命中的规则翻译成业务人员能看懂的话；② 生成报告文字段落；③ 实训场景中的问答式讲解（充当「带教师傅」） | 只能改写已判定的事实，**不得新增、不得推翻判定结论** |

> 解读层的输出必须可被溯源：LLM 生成的每段话都要能指回具体的 Finding。禁止 LLM 自由发挥补充未经计算的风险点。

### 3.3 审计与出题互为逆运算

```
审计模式（正向）：真实账套 ──→ 规则引擎 ──→ 风险清单（带证据）
出题模式（反向）：目标规则 ──→ 规则引擎 ──→ 带标注题库（带标准答案）
```

**规则库是唯一真相源。** 出题器读取规则的 `inputs` 与 `threshold`，反向构造能命中（或刻意不命中）该规则的数据，即可自动生成题目与标准答案。同一份规则定义，两个执行方向，**无需另建题库系统**——这是产品结构上的白送能力。

### 3.4 输出三层结构

| 层 | 面向 | 内容 | 缺了会怎样 |
| --- | --- | --- | --- |
| **警示层** | 经营管理者 | 风险等级（高/中/低）+ 一句话结论 | 用户不知道该先看哪条 |
| **证据层** | 会计、教师 | 指标值 + 计算过程 + 偏离度 + 法条依据 + 建议动作 | **产品变成黑盒，价值归零** |
| **实训层** | 学生、教师 | 漏检项 + 误报项 + 得分明细 + 标准答案 | 实训退化为「答案对不对」的判分器 |

### 3.5 术语表

| 术语 | 定义 | 注意 |
| --- | --- | --- |
| 标准指标 | 由原始科目 / 申报项聚合而来、规则引擎唯一识别的内部口径量（如「营业收入」） | 规则只认标准指标，不认原始科目 |
| 标准化 | 把各财务软件不一致的科目编码与期间口径，统一映射为标准指标的过程 | **最脏也最核心的一步，是隐藏护城河** |
| 条件规则 | YAML 声明的 if-then 字段比对 / 阈值判定 | 占规则库约 90% |
| 图规则 | 基于节点与关系网络的模式匹配（关联方、关联交易） | 占约 10%，**独立引擎，不与 YAML 混用** |
| 证据卡 | 一条风险的完整举证单元 | 产品核心资产 |
| Finding | 一条规则的执行结果，状态为 hit / pass / skipped | `skipped` 不等于 `pass` |
| 全电发票（数电票） | 本身即结构化电子数据，可从电子税务局批量获取 | **不需要 OCR** |
| 四流一致 | 合同流 / 发票流 / 资金流 / 货物流的一致性校验 | P2 能力 |

## 四、功能需求

### 4.0 编号与优先级规则

- 编号格式：`FR-<模块字母><两位序号>`，如 `FR-A01`
- 优先级：**P0**＝MVP，必做且做了才算跑通；**P1**＝产品成立必需；**P2**＝能力全貌补全
- 状态标记：✅ 已实现 ｜ 🔨 部分实现 ｜ ⬜ 未开始 ｜ 🚫 明确不做
- **所有 FR 均在范围内，不存在「砍掉」的条目**，只有期次差异

### 4.1 模块 A — 多源数据采集与标准化

**设计判断**：主输入是「科目余额表 + 申报表 + 发票汇总」，**不是「一叠发票照片」**。前者已聚合、带会计含义；后者原始、异构、需识别。

| FR-A02 | 科目映射与标准化 | 按映射表将原始科目聚合为标准指标，记录来源与计算过程 | P0 | ✅ |

| FR-A08 | 银行流水导入 | 网银导出的结构化流水，用于账面vs流水交叉校验 | P1 | 🔨 结构化流水已接入，调节口径仍须人工复核 |

| FR-A13 | **RPA 采集** | 在沙箱环境内模拟从财务软件/电子税务局自动取数 | P2 尾期 | ✅ 本机纯合成门户采集；真实门户未接入 |

**FR-A09 上传前企业选择与信息核对（已接入本地代码）**：上传页默认新建，也可明确选择有权访问的已有企业；允许提前填写名称、税号、行业、地区、本期纳税人身份、业务范围及主期间。新建空项仅由无歧义材料候选预填；已有企业使用档案与最近确认信息作参考，不沿用旧期间。手填不被原文覆盖，来源分别保留，主体及期间冲突阻止确认；可选业务信息差异提示核对，不授予优惠资格。确认才建立或复用机构内稳定企业标识；旧税号格式差异不重复建档，多个歧义档案须明确选择，不静默改名、变更负责人或改写旧审计。图谱企业节点与档案关联，但仍展示单次审计，不代表跨期知识库完成；24条原规则不因此更改。

**FR-A03 关键要求（P0 必须补完）**

1. 缺工作表 / 表头不符 → 明确报错，指出期望与实际
2. 缺某个指标 → 依赖它的规则标记为 `未执行`，并写明「缺什么、去哪补」
3. **绝不把「缺数据」当作「无风险」** —— 这是审计类产品的致命错误

企业财务导出补充约束：币种与金额缩放分开，已声明的外币、未知或空币种不可默认为人民币；逐行币种不能任意向下填充，只读取原件真实合并范围。支持元、千元、万元、百万元、亿元的明确人民币换算，不进行汇率转换。原文完整月、季、半年及起止区间与金额栏次相匹配，单个报表日期不是完整业务期间；不支持或冲突的原文期间不能用企业主期间或手工映射掩盖。此增量属于企业材料业务，与其页面、接口及测试一同交付；其他软件格式、实际金额效果及完整外部账套仍待验收。

旧企业财务导出批次须校验适配契约、相关源码/依赖指纹和最近一次本地解析状态，不能因历史快照曾可确认就继续放行。更新适配后保存重分析，从留存原字节重新解析，清除数值修正与旧复核，不能同时提交新数值修正来批准旧映射；排除材料不重读，恢复后再核对。页面区分旧候选与可复核的新解析，原件、历史版本及已生成结果保留，不自动调用 AI。

同样约束企业 PDF：解析版本、相关源码/pdfplumber/pdfminer.six 指纹或本地状态未知、不一致时，同一原页片段也不能直接沿用可确认缓存。保存须从完整留存原字节重读当前片段，清除旧金额编辑及复核，不能同时提交非空金额或复核来批准旧解析；复核编号绑定解析版本及程序指纹。排除不重读、恢复再解析，已生成报告及重复确认引用不改写。旧片段不能直接授权入队，排队后解析适配变化也须在发送模型前拒绝，先完成本地核对，再单独重新授权。

**关于 OCR 与 RPA 的正式口径**

- 全电发票本身就是结构化电子数据，可直接从电子税务局批量获取。因此「OCR 识别发票」的适用场景收敛为**纸质票 / 扫描件 / 拍照件等脏数据兜底**，不再是核心技术路径。
- RPA 优先级最低：沙箱场景可用价值有限，真实系统对接成本极高，排在 P2 尾期。

**FR-B06/B07/B08 —— 三类比对的规则落点**

所有风险来源可归为三类比对，规则库按此组织，**不存在第四类**：

| 类型 | 定义 | 是否需要外部数据 | 代表规则 |
| --- | --- | --- | --- |
| **内部勾稽** | 账内自洽性，仅凭企业自身材料校验 | 否 | R-001 收入未足额申报；R-002 增值税账申勾稽不符 |
| **外部交叉** | 账面 vs 外部真实数据（金税四期核心逻辑，最有说服力） | 是 | R-004 个税社保人数不匹配 |
| **指标偏离** | 横向（同地区同行业）/ 纵向（同比环比）对标 | 需行业基准值 | R-003 增值税税负率异常 |

**FR-B09 —— 图规则与条件规则的边界（重要，易错）**

> ⚠️ **不要把「YAML 条件规则」与「图查询」混为一谈。**
> - 条件规则是 **if-then 求值**：「利润表收入 比 申报销售额 高 10% 以上」—— 与图无关。
> - 图规则是 **关系网络遍历**：「找出 A 的股东 → 这些股东控制的其他公司 → 它们之间的交易」。

**FR-E04 —— 评分设计的关键要求**

评分标准本身的合理性，**是教师认可度的关键**。三条硬要求：

1. **有标准答案，且答案来自规则库**（不是人工编的），保证答案与审计引擎口径一致
2. **误报要扣分，但必须解释**「为什么它不构成风险」——否则学生无法从错误中学习
3. **不设「全对才算过」**，按风险点分别计分，让部分正确也有正反馈

> 学生查出的风险点与出题时注入的风险点，是同一份规则库的两个方向。**出题与评分天然自洽**，这是架构带来的优势，不是额外工作量。

财务导出适配保留原工作表、源单元格、原单位和栏次，区分当期/累计、借/贷发生额与余额；用户补齐单位、期间或金额栏次后须保存重新解析并明确复核，不覆盖原文明确事实。非标准工作表名仅在原文标题或唯一科目表头明确时识别。混合主体/期间、时点或重复表类阻止检测，允许逐工作表排除后从留存原件重检；恢复或改映射清空当前数值修正和复核，旧版本与标准企业信息归属锚点保留。CSV/TSV 保留原记录位置，不按文件名替代原文表类。PDF 原件最多 300 页，长文件须先选择不超过 50 个连续原始页；候选与检测来源保留原页码和未读取范围，切换片段清除当前金额编辑及复核，旧版本保留。已支持财务金额单元格区分原公式、文件缓存候选及用户固定值；默认留空，明确采用或补填后逐项复核，修改即使旧复核失效，来源保留三者及单位换算。错误、非数值或缺缓存不补零；数值缓存或人工复核不能证明计算正确或已经更新。其他未识别表头、实际公式金额核验及完整外部账套的端到端效果仍须扩展验证；公式不执行，原件不改写，不能用零填补缺失来通过检测。

AI 候选须区分申报表、账簿与财务报表取数口径，对照表金额列归属不清时不得采用；申报金额不能直接补入账面或财务报表指标。项目行名称不能代替金额栏标题，原始表类未确认、数值缺失或证据有疑点时不标为已验证。PDF 期间原文允许仅去除排版空白后匹配，但保留原始引用，多个期间标题不能合并成单一期间证明。所选核对期不是原件事实，模型契约失败不降级放行；逐项人工复核门槛继续保留。企业页面先保存片段做本地解析，再单独授权 AI；请求固定原件指纹、原始页码、核对期及模型服务进入持久化队列，不重发未知结果的中断任务。新候选清除所选文件旧编辑和复核，保留其他材料与冻结版本；发送前及结果写入时复查权限和版本。该网页闭环已通过仿真 HTTP 及桌面/窄屏检查，真实模型在此流程下的稳定性、实际扫描件及完整外部材料闭环仍待验收。

真实公开 PDF 的文字/图像候选验证已覆盖金额和单位核对、错误补零与口径误映射拒绝；公开扫描资产负债表另完成同批次 AI 候选、人工核对、复核、确认及 HTML/PDF 流程。该单表只支持一项勾稽检查，不代表整份材料或模型稳定性通过，不取消人工复核；失败记录与剩余范围见 [企业材料验证边界](../TODO.md#企业材料验证边界)。

原始扫描财报视觉验证发现模型会将报表日期推测成完整业务期间。单个日期与无可验证文字依据的纯图像期间候选现单独留存，不作为原文完整期间采用；需对照原图和期间说明补齐并复核。时点与主期间终点冲突不能由补填绕过；单个报表日期不能证明上期金额属于上年同期，相关标准金额保持缺失。候选观察变化使旧复核失效，企业页面及确认快照明确 AI 企业/期间仍为候选。真实扫描调用已有取数成功、数值/引用不一致拦截及契约拒绝记录；扫描质量、完整材料闭环和模型稳定性仍待扩大验证。

企业材料页面对短 PDF 也提供明确选页入口；普通企业信息与金额修改不自动生成片段或清除当前编辑。修改页码或选用所填片段后，先保存本地重读，再另行授权发送。只读原始 AI 候选与证据来自服务器留存解析，不被用户金额或口径说明覆盖。真实扫描网页验证已覆盖单页授权、候选核对、人工修正及刷新恢复；营业收入曾同时出现错误候选和错误引用，程序无法仅凭两者一致识别该类 OCR 错误，必须对照原图。该验证保持缺失税号与正式确认禁用，不代表全部识别准确、完整外部账套或正式检测/报告验收。

企业 XLSX 的打印设置不参与财务取数：仅兼容原生部件类型、工作表页面引用、结构和大小均可核对的 DEVMODEW 元数据，不调用打印驱动、不向模型发送；未知二进制、伪造关系、宏、外链及嵌入对象仍拒绝。公开外币原始 XLSX 已验证原件格式及真实公式缓存读取，但英文表类未适配，业务金额未采用；算术一致不证明缓存时效，不计为人民币导出、完整账套或正式检测验收。该适配与证据归于企业材料业务，不混入高校教学功能。

### 5.3 规则 YAML 规范

**必填字段**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | str | 唯一，格式 `R-xxx` |
| `name` | str | 规则名称（业务语言） |
| `category` | str | 分类：收入完整性 / 税会勾稽 / 指标偏离 / 外部交叉 / … |
| `tax_type` | str | 税种：增值税 / 个人所得税 / 企业所得税 / … |
| `severity` | enum | `high` / `medium` / `low` |
| `logic` | map | 求值定义（见下） |
| `evidence` | list | 需要展示的指标清单，**让「可举证」成为规则固有属性** |
| `legal_basis` | list | 法条依据 |
| `suggestion` | str | 建议动作 |

**可选字段**：`description`（规则说明，供教师/会计理解）

**2.0规则包新增必填字段**：`version`（规则版本）、`inputs`（指标→取数口径/来源映射）、
`scope`（适用范围）、`threshold_basis`（阈值出处）、`references`（官方直接链接）。
分类统一为内部勾稽/外部交叉/指标偏离；公式依赖、inputs、evidence必须一致。
实际格式及迁移说明见 `03-核对规则目录与使用说明.md`，旧示意YAML需补齐元数据。

**三种 logic 类型**

| type | 判定 | 参数 |
| --- | --- | --- |
| `deviation` | `\|left − right\| / \|right\| > threshold` | `left` `right` `threshold` |
| `amount_mismatch` | `\|left − right\| > tolerance` | `left` `right` `tolerance` |
| `ratio_range` | `numerator / denominator` 落在 `[min, max]` 之外 | `numerator` `denominator` `min` `max` |

补充：三种基本类型可通过`all.conditions`组合；操作数支持`add/sub/mul/div/min/max`白名单公式。
比率及相对偏离分母须大于零，否则未执行；金额采用Decimal，阈值等值不命中，区间为闭区间。

**设计要点**：每条规则自带 `evidence` 与 `legal_basis`。会计/教师可参与编写规则，**无需写代码**——这是规则库能持续扩张的组织前提。

### 5.4 证据卡规范（产品核心资产）

每条命中风险必须可展开为如下结构：

```
风险类型：收入未足额申报
风险等级：高
命中规则：R-001 账面收入 vs 增值税申报销售额相对偏离度 > 10%
触发明细：
  营业收入                   1,280,000.00   ← 主营业务收入 + 其他业务收入（本期贷方发生额）
  增值税.销售额                860,000.00   ← 增值税申报表—销售额
  绝对差额                    420,000.00   （计算值）
  相对偏离度                      48.84%   阈值 10.00%
计算过程：|1,280,000.00 − 860,000.00| ÷ |860,000.00| = 48.84%，阈值 10.00%
法条依据：《中华人民共和国增值税法》第三条、第七条
          《中华人民共和国税收征收管理法》第二十五条、第六十三条
          《中华人民共和国会计法》第九条
建议动作：核查账面收入与申报销售额的差异构成，逐笔比对是否存在未开具发票但已实现的收入、
          应视同销售的业务，以及跨期确认问题。若属已实现收入未申报，应及时更正申报并补缴
          税款及滞纳金。
```

**硬要求**

| # | 要求 | 理由 |
| --- | --- | --- |
| 1 | 每个数值必须标注**取数来源** | 否则无法追到原始凭证，等于不可举证 |
| 2 | 必须展示**计算过程**，而非只给结果 | 评委/教师会追问「这个 32.8% 怎么来的」 |
| 3 | 必须给出**阈值与依据** | 说明「为什么 32.8% 算异常，10% 不算」 |
| 4 | `skipped` 必须显式展示 | 缺数据不等于无风险，隐藏此状态即失职 |

## 九、风险与对策

| # | 风险 | 可能性 | 影响 | 对策 |
| --- | --- | --- | --- | --- |
| 1 | **证据链未通就先堆规则**（最大风险） | 高 | 致命 | 铁律：P0 只做 1 条规则的完整闭环，Web 页面上能看到证据链前，不新增规则 |
| 2 | 真实企业数据用于教学，构成数据泄露 | 中 | 致命 | 红线：沙箱只用仿真数据；建仿真数据生成脚本，禁止导入真实账套 |

| 4 | 规则质量参差，误报率高 | 高 | 高 | 每条规则配正例/反例样例；L2 规则引入前必须通过样例回归 |
| 5 | 标准化映射覆盖不足，材料导入即失败 | 高 | 高 | 优先支持 1–2 家主流财务软件导出格式；提供字段映射配置界面 |
| 6 | LLM 解读层越界改写判定结论 | 中 | 高 | 架构约束：LLM 只能改写已判定事实；输出必须可溯源到 Finding；不做自由生成 |
| 7 | 团队人力不足导致 P1 延期 | 中 | 中 | 排期按 P0→P1→P2 严格串行；P1 内可按模块并行 |

| 10 | 报告免责声明缺失引发误用 | 低 | 中 | 报告内固定免责段落，不可配置移除 |
