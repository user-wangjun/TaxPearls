# 税海拾珠 · 运行、备份与恢复

## 本机运行

使用 `python -m webapp --host 127.0.0.1 --port 8000` 启动，`/healthz` 用于存活检查。数据库由 `TAXPEARLS_DB` 指定，默认写入 `instance/taxpearls.db`。配置文件使用 `.env`，填写前从无密钥的 `.env.example` 复制。Web 启动必需配置独立的 `TAXPEARLS_FIELD_KEY`（32 字节随机密钥的 Base64）；缺失或与数据库绑定不匹配时拒绝启动，不自动生成或替换密钥。已有数据库先按下方停服迁移步骤处理。

Windows 使用本机 Chrome 导出 PDF；Linux 容器配置 `TAXPEARLS_PDF_BROWSER=chromium`。固定依赖见 `requirements.lock`。企业材料原件、分析和确认版本已持久化；兼容教学草稿仍在进程内存中。本机分析并发控制按单进程执行，多副本部署须另行验证。

本机、CI 与正式运行使用各自独立的数据库和配置。统一检查入口自动使用临时数据库并关闭外部模型和邮件发送，不使用业务库执行回归；CI 的只读仓库权限和测试通过不等于正式部署已完成。

## 备份、验证与恢复

使用 SQLite 在线备份 API 在内存中捕获已提交的 WAL 数据，再用 AES-256-GCM 认证加密生成 `.tpbackup` 文件；不生成中间明文备份。密钥 `TAXPEARLS_BACKUP_KEY` 必须是独立的 32 字节随机密钥的 Base64，并通过安全方式注入进程环境。运维脚本不自动加载 `.env`，也不接受命令行密钥；请将密钥与备份分开保管。

```powershell
python scripts/ops_db.py backup-encrypted --database instance/taxpearls.db --output backups/checkpoint.tpbackup --retention-days 30
python scripts/ops_db.py verify-encrypted backups/checkpoint.tpbackup
```

示例的 30 天仅是参数示范，实际保留期由业务与运维要求决定。校验会检查密钥、认证标签和数据库完整性，密钥错误或内容被修改时拒绝恢复。已有输出文件不会覆盖。

恢复须同时注入原字段密钥 `TAXPEARLS_FIELD_KEY`、备份密钥及源库对应的环境/实例配置。先校验来源身份，覆盖已有目标前再校验目标身份；另一个环境或实例的数据库不能被替换。脚本先在内存中验证字段密钥与全部受保护载荷，必要时转换并压缩，再准备替换目标；错误密钥不会生成目标安全副本或替换目标。恢复会替换指定数据库。先停止应用服务，再执行；残留 WAL 须在原环境配置下使用显式检查点处理，不能直接删除。脚本检测 SQLite 日志和运维锁，先生成并验证现有数据库的加密安全副本，随后恢复。恢复期间若目标数据库发生变化则取消覆盖。

```powershell
python scripts/ops_db.py restore-encrypted backups/checkpoint.tpbackup --database instance/taxpearls.db --safety-retention-days 30 --yes
```

恢复返回安全副本位置；需要回退时仍须停服，以该 `.tpbackup` 副本为恢复输入。密钥、数据库、备份和回执均不纳入 Git。明文兼容命令 `backup` 和 `restore` 仅供迁移或测试，必须明确提供 `--allow-plaintext`；明文恢复还需 `--yes`。

## 保留期与销毁回执

```powershell
python scripts/ops_db.py retention-plan backups
```

该命令只预览经过认证且已到期的备份，不按文件修改时间判断，也不执行删除。存在同名 `.hold` 标记的备份受到保护。

`destroy-encrypted` 默认仅预览，须指定一个备份、所属目录、预期 SHA-256 与原因。实际执行还需明确传入 `--yes` 和目录内的 `--receipt` 回执路径。工具核对文件与摘要、到期状态、保留标记及硬链接，防止误删已变化的目标；回执带有独立用途的 HMAC 认证，可用 `verify-receipt` 验证。认证通过仍须核对回执状态；中断状态需要人工核查，不能视为销毁完成。回执记录文件删除操作，不证明底层存储已完成物理擦除。

## 冻结报告导出

`scripts/export_audit_pdf.py` 从只读数据库导出已归档版本，先验证内容指纹，不重新计算规则或生成报告。PDF 尚未归档时会提示失败，可改用 `--format html` 导出冻结 HTML；已有输出文件不覆盖。运行者须具有读取该数据库的权限，并配置其原字段密钥 `TAXPEARLS_FIELD_KEY`；导出前解密和验证，数据库保持只读。

```powershell
python scripts/export_audit_pdf.py --list
python scripts/export_audit_pdf.py AUDIT_ID --version 1 --output output/saved.pdf
```

## 容器配置

`Dockerfile` 提供固定依赖、Chromium、中文字体与非 root 用户；包源默认 PyPI，可用 `TAXPEARLS_PIP_INDEX_URL` 指定受控源，不降级锁定依赖。`.dockerignore` 排除 Git、环境密钥、本机依赖、数据库、备份和报告。

每个安装使用自己的受控外置配置，明确填写 `TAXPEARLS_ENVIRONMENT`、独立 `TAXPEARLS_INSTANCE_ID`、配置文件路径 `TAXPEARLS_ENV_FILE`、版本标签 `TAXPEARLS_IMAGE_TAG` 和回环端口 `TAXPEARLS_BIND_PORT`。Compose 不默认镜像版本，按实例 ID 命名项目、数据卷和网络，只向回环地址发布端口；不同容器或卷不等于不同物理主机。下列路径须替换为该环境实际受控配置：

```powershell
docker compose --env-file C:/受控配置/production.env config --quiet
docker compose --env-file C:/受控配置/production.env build
docker compose --env-file C:/受控配置/production.env up -d --no-build --pull never
```

这些文件是运行配置，本地 Python 回归不等于容器或生产环境验收。正式部署仍需配置 HTTPS、可信代理、`TAXPEARLS_COOKIE_SECURE=1`、持久化目录访问控制，并验证备份恢复与邮件链路。

## 邮件配置

配置 `TAXPEARLS_RESEND_API_KEY`、`TAXPEARLS_EMAIL_FROM_ADDRESS` 和 `TAXPEARLS_EMAIL_FROM_NAME`。发件地址须使用已在服务方验证的域名。`TAXPEARLS_PUBLIC_BASE_URL` 用于邮箱认证及密码重置链接，只接受可信源站，不带路径、查询、片段或用户信息；正式环境必须显式填写自己的 HTTPS 地址，同时配置 `TAXPEARLS_COOKIE_SECURE=1`。本机留空时仅允许 localhost、127.0.0.1 和 ::1 回退；外部请求缺少可信基址时拒绝申请，不使用客户端 Host 拼接链接。

邮箱验证码登录、邮件链接确认与密码重置均绑定发起浏览器；打开链接不会自动认证，凭证需明确确认且只能使用一次。重置成功后撤销已有会话；未知邮箱与已绑定邮箱的重置申请获得一致响应。外部环境须明确配置可信 HTTPS 基础地址，不能依赖请求 Host 生成邮件链接。接口回归使用模拟发件，真实送达须另行验证。需要实际发信时可手动运行 `scripts/send_test_email.py --to person@example.com`，应换成获准的真实收件地址。

须在发起申请的同一浏览器、同一站点完成确认；邮件内置浏览器与原浏览器不一致时，可回到原浏览器或重新申请。六位验证码和独立长令牌共用有效期，重发使旧凭证失效；成员停用或密码重置撤销待用凭证，恢复成员不会复活凭证。短期确认结果仅留在当前页面内存，刷新后需重新申请。

邀请和邮箱链接可能携带持有者凭证。代理、CDN、APM 和前端遥测须对凭证路径与敏感参数脱敏，不记录请求体中的验证码、令牌、密码或 Cookie。页面清除地址栏凭证及发送缓存/来源限制头不能替代外部日志配置。正式环境还须验证 HTTPS、邮件域名、真实送达和日志脱敏。

## 企业材料密钥与恢复

企业上传须配置 `TAXPEARLS_MATERIAL_KEY`：独立的 32 字节随机密钥，以 Base64 编码。服务从进程环境读取，Web 启动时也加载本机 `.env`；不要复用模型、邮件或备份密钥。未配置或密钥格式无效时拒绝上传，不自动生成密钥，也不降级明文存储。

原件字节、文件名、分析、修改与确认载荷认证加密保存，数据库备份包含这些密文及关联记录。恢复到独立服务时须同时注入原材料密钥，只有备份密钥不能解密企业材料；丢失材料密钥无法恢复原件内容。密钥不得与数据库或备份一起提交。

管理员明确删除原件前展示关联结果、重检和备份副本影响；已有确认快照及冻结报告保留，备份中的原件副本可能仍存在，不宣称介质彻底擦除。请求日志在重启后保留已提交、失败或未完成状态；响应未知时先查已有结果，不直接重复确认。

## 敏感字段加密与离线迁移

当前客户标识、审计数据和风险证据、冻结报告 HTML/PDF 与清单、机构汇总、仿真出题载荷、模型结果、日志详情和教学提交详情/反馈使用 AES-256-GCM 列级认证加密。加密绑定表、列及记录身份，明文或跨记录替换拒绝写入；业务编号、日期、统计值保持可查询，客户等值索引使用机构范围内的 HMAC，不代替权限检查。

`TAXPEARLS_FIELD_KEY`、`TAXPEARLS_MATERIAL_KEY` 与 `TAXPEARLS_BACKUP_KEY` 分别保管，不得复用。字段密钥丢失会使已有证据不可读，应用不会通过更换密钥重置数据。Web 从受控配置读取，运维脚本须在进程环境注入密钥，不自动加载 `.env`，不接受命令行密钥。

已有数据库先停止服务并确认 SQLite 连接关闭，再明确指定保留期和执行确认：

```powershell
python scripts/ops_db.py migrate-fields --database instance/taxpearls.db --safety-retention-days 30 --yes
```

工具先在内存中校验、转换并压缩，生成经过认证的 `.pre-fields-*.tpbackup` 安全副本，随后只将加密后的压缩数据库写入临时文件并替换目标。失败时保留原目标，目标若在迁移期间发生变化则取消替换；完成后须复核客户归属、审计及冻结报告内容。启动时转换字段不等于清除已有空闲页或日志中的明文，已有业务库应使用上述停服步骤。文件压缩不证明磁盘、其他备份或已删除副本已完成物理擦除。

恢复加密备份会在内存中验证字段内容及查询索引，转换尚未加密的兼容载荷，再发布目标数据库；访问企业原件另须原材料密钥。安全副本保存迁移前结构，但当前恢复入口会转换至当前字段格式；回退应用前须另行核对代码、数据结构与密钥兼容性。真实业务库迁移及生产密钥保管仍须单独验收。

## 部署身份、检查点与兼容回滚

`TAXPEARLS_ENVIRONMENT` 支持 `local`、`training`、`production`。本机未指定时使用 local；培训和生产必须明确独立实例 ID。数据库中的环境/实例身份由字段密钥认证，结构安装前以及运行中的每次连接都校验；即使字段密钥相同，跨环境或跨实例访问也拒绝。生产模式要求可信 HTTPS 基址、`TAXPEARLS_COOKIE_SECURE=1` 和三种独立的 32 字节存储密钥，拒绝通配信任代理。配置检查不证明实际 TLS 或宿主机隔离已经验收。

新空库绑定当前身份。已有业务库若无身份标记，非本地环境不能自动认领；确需首次绑定时，先停服并保管原密钥和可验证的加密安全副本。显式绑定只接受无标记库或本地库，不能重标另一个已绑定的培训/生产实例；绑定不执行数据脱敏，也不代替业务数据迁移授权。教学只使用明确的仿真材料。

停服后若残留 SQLite WAL，先在原环境配置下执行：

```powershell
python scripts/ops_db.py checkpoint --database instance/taxpearls.db --yes
```

检查点由 SQLite 保存已提交的 WAL 数据，检查完整性和活动写锁，再关闭 WAL 模式；不直接删除日志。返回的 `application_stopped_verified=false` 表示工具不能证明空闲应用已经停止，操作者仍须确认所有服务和连接关闭。检查点前保管有效加密备份；服务下次启动会重新使用 WAL。

然后通过受控进程环境注入目标环境/实例和原密钥，执行明确的停服绑定：

```powershell
python scripts/ops_db.py bind-environment --database instance/taxpearls.db --safety-retention-days 30 --yes
```

绑定在内存中验证、转换和压缩，发布前保留加密安全副本；不修改其他已绑定环境的身份。恢复与只读冻结报告导出也校验运行环境/实例。

应用回滚必须保留两个不同 image ID 的发布标签，核对数据结构、部署身份与字段/材料密钥格式兼容性；不能直接用迁移前应用读取加密库，也不能以报告可读代替安全保护仍有效。切换镜像前安排停服窗口，必要时恢复匹配的数据备份，随后核对原会话权限、原件、冻结 HTML/PDF 字节及跨环境访问拒绝。

可用一次性本机合成数据工具验证兼容镜像：

```powershell
python scripts/check_deployment.py --image candidate --rollback-image compatible
```

两种本地镜像须事先构建，且标签对应不同 image ID；工具不拉取、不构建，也不读取用户 `.env`。它为培训和生产生成独立临时配置、密钥及 Compose 项目，检查上传确认、原件/PDF、卷/网络/会话隔离、跨环境恢复拒绝、停服恢复和兼容镜像回滚；回滚后再次检查部署身份保护。只清理本次生成的唯一项目和卷，不执行全局清理。

当前隔离数据库回归与 Compose 配置解析已验证；本机 Docker 引擎未启动，本轮未执行实际容器恢复或镜像回滚。生产物理隔离、真实 HTTPS、生产密钥保管及目标服务器验收继续保留。

## 后续安全与部署验收

企业原件与材料版本载荷、当前业务及错题重练敏感证据列已使用独立密钥认证加密留存，离线迁移、部署身份及恢复校验已接入；兼容镜像回滚验证工具已提供，实际容器演练与生产物理隔离仍须验收。

- 原件、敏感字段和备份分别确定密钥用途与管理范围；密钥通过受控配置注入，不写进文档、日志、命令行或版本控制。企业原件密钥与备份密钥分别保管，实际部署须验证权限、下载、备份恢复及删除影响。
- 当前敏感字段读取、写入、兼容库转换与失败恢复使用隔离数据验证；真实业务库须按停服步骤保留可验证的安全副本，恢复后检查机构归属与结果一致性。新增业务模块须同步适配其敏感字段。
- 演示、教学与生产分别确定数据、运行用途和实例身份，恢复前校验目标与格式；相同企业标识不能跨机构或环境授权访问。容器启动不等于已经完成生产隔离。
- 回滚须核对目标代码、数据结构与密钥格式的兼容关系；不能只切回应用版本而忽略数据升级。真实部署、密钥保管与物理环境隔离须单独验收。

## 通知邮件

`TAXPEARLS_NOTIFICATION_EMAIL_ENABLED=0` 为默认值。启用摘要邮件还须配置邮件密钥与已验证的发件地址，且接收人本人同意邮件订阅。队列保存摘要、幂等键及投递状态，服务重启后可继续处理；已被服务方受理的投递不重复发送，未知响应需按状态申请重试。站内通知不依赖邮件服务。

当前仅安装邮件投递适配器。多渠道队列、会话确认绑定、一次性身份流程与绑定撤销属于基础实现，外部 IM 或第三方身份提供方的公开接口、令牌验证与页面尚未接入；无需填写额外外部服务密钥。未配置邮件密钥不影响审计结果和站内通知保存。
