## 一、对齐结论（2026-10-09）

本文档初稿提出的管理端四表方案（`university_admins` / `training_tasks` / `training_submissions` / `training_scores`）为早期设计稿。2026-10-08 起，实训评分存储以 teaching-training 分支提交 567fb29 的**六表方案**为实现基准（`webapp/schema.py` + `src/models.py`，已按追加式惯例落库本地主数据库），原四表方案中重叠的三张表**由六表取代**，对应关系如下：

| 初稿四表（已取代）        | 现行六表                                | 说明                                     |
| ---------------- | ------------------------------------ | -------------------------------------- |
| `training_tasks` | `training_task` + `score_rule`       | 任务与判题/评分规则配置拆为两表；暂不含语言、难度等代码判题字段       |
| `training_submissions` | `student_submit` + `student_info` | 学生实体独立建表；提交为覆盖式（见三.1 设计要点），暂无历次提交版本    |
| `training_scores` | `score_result`                       | 1:1 只留最终评分与明细；暂无教师评语与 auto/teacher 分离  |
| `university_admins` | ——（保留，见第四节）                        | 管理端表不属实训评分域，保留为待开发设计稿，待按 FR-U01～U06 重审 |

四表方案中以下设计要素**不废弃**，列为后续演进的待吸收项（见三.2）：历次提交（`attempt_no`）、教师评语、自动分/教师分分离（`score_source`）、判题失败状态（`judging`/`failed`）、提交内容摘要（`file_hash`）。

## 二、设计约定（以六表现行为准）

1. **主键**：统一 `id TEXT PRIMARY KEY`，应用层生成 UUID 字符串；
2. **隔离键**：实训域当前以 `college TEXT`（院校名称文本）作隔离键，**不是**指向机构表的 `org_id` 外键；`task` 与 `student` 冗余 `college` 键，与创建者院校的一致性由服务层保证。与主库机构体系如何打通，留待接口开发时评估；
3. **时间字段**：统一 `TEXT`，存 ISO-8601 字符串；
4. **布尔值**：统一 `INTEGER`（0/1）；分数用 `REAL`，JSON 存 `TEXT`（`*_json` 后缀）；
5. **外键**：声明 `REFERENCES xxx(id)`，删除策略由业务层控制，不启用级联；**SQLite 需连接执行 `PRAGMA foreign_keys=ON` 外键才生效**；
6. **敏感字段**：密码只存哈希；邮箱、手机号、提交正文等按 05 号文档走字段级 AES-256-GCM 加密，密文仍存 `TEXT` 列；
7. **建表方式**：追加式 `CREATE TABLE IF NOT EXISTS`，不改动既有表结构。

## 三、实训评分六表（已实现，以代码为准）

权威定义：teaching-training 分支 `webapp/schema.py`（建表 SQL）与 `src/models.py`（一一对应的 @dataclass，不做 ORM 映射）。建表顺序即外键依赖顺序：`college_user → training_task → student_info → student_submit → score_result → score_rule`。

| 表               | 作用                     | 关键列与约束                                                                                                             |
| --------------- | ---------------------- | ------------------------------------------------------------------------------------------------------------------ |
| `college_user`  | 实训管理员（教师账号）            | `username UNIQUE`、`college NOT NULL`（隔离键）、`role`（teacher/admin）、`active`；索引 `(college, active)`                    |
| `training_task` | 实训任务                   | `dataset_json`（仿真数据集）、`created_by → college_user(id)`、`starts_at/ends_at`（CHECK 截止不早于开始）、`published`（0 草稿/1 发布）     |
| `student_info`  | 学生档案（含登录口令哈希）          | `UNIQUE(college, student_no)`、`class_name`（文本，暂无班级实体表）、`active`                                                     |
| `student_submit` | 学生提交（覆盖式，每任务每人一条）      | `task_id`/`student_id` 外键、`answers_json`、`status`（submitted/scored/reviewed，CHECK 枚举）、`UNIQUE(task_id, student_id)`   |
| `score_result`  | 评分结果（与提交 1:1）          | `submission_id UNIQUE`（1:1）、`total_score REAL`（允许为负）、`missed_count`/`false_positive_count`、`detail_json`、`scored_by` |
| `score_rule`    | 任务内评分规则                | `task_id` 外键、`UNIQUE(task_id, name)`、`category`（omission/false_positive/evidence，CHECK 枚举）、`weight`、`config_json`     |

索引：`idx_college_user_college(college, active)`、`idx_training_task_college(college, created_at DESC)`、`idx_student_info_college(college, active)`、`idx_student_submit_task(task_id, submitted_at DESC)`、`idx_student_submit_student(student_id, submitted_at DESC)`、`idx_score_rule_task(task_id, enabled)`。

### 3.1 设计要点

1. **覆盖式提交**：`UNIQUE(task_id, student_id)` 表示每任务每生仅一条最新提交（沿用既有 `submissions` 惯例），**不保留历次提交**；
2. **最终评分制**：`score_result` 与提交 1:1，只留最终得分与明细，教师调分历史需靠应用层日志承载；
3. **业务隔离**：`task`/`student` 冗余 `college` 键，服务层须校验其与任务创建者院校一致；
4. **外键生效条件**：SQLite 连接必须开启 `PRAGMA foreign_keys=ON`。

### 3.2 已知缺口（对照 PRD 4.5，FR-E01～E11）

以下缺口在六表设计检查中确认，**留到接口/页面开发时补齐**（追加式建表 + `ALTER TABLE` 兼容既有库）：

1. `score_result` 无教师评语字段（FR-E07 要求加评语）；
2. 无班级实体表：`student_info.class_name` 仅文本，无法支撑切班/班级授权（FR-E08）；
3. 无错题本表（FR-E11），且覆盖式提交 `UNIQUE(task_id, student_id)` 与独立重练/订正的多次作答冲突；
4. FR-E10 统计口径变化标记无字段承载；
5. 组卷层级由 `training_task.dataset_json` 单字段承载（取舍项）。

演进时优先吸收第一节所列初稿要素（`attempt_no`、`teacher_comment`、`score_source`、`judging/failed` 状态）以化解缺口 1、3。

### 4.1 管理员表 `university_admins`（设计稿）

高校管理端管理员档案，与现有 `users` 账号表一一关联，表达校级/院系两级管理视角。

| 字段            | 类型      | 说明                                            |
| ------------- | ------- | --------------------------------------------- |
| id            | TEXT    | 主键，UUID                                       |
| org_id        | TEXT    | 所属院校机构 ID，关联现有机构，NOT NULL，机构隔离依据              |
| user_id       | TEXT    | 关联账号 ID（`users.id`），UNIQUE NOT NULL，一人一档案     |
| username      | TEXT    | 登录名，机构内 UNIQUE NOT NULL                       |
| display_name  | TEXT    | 姓名，NOT NULL                                   |
| admin_level   | TEXT    | 管理层级：`school`（校级）/ `department`（院系级），NOT NULL |
| department_id | TEXT    | 院系 ID；`admin_level = school` 时为空，院系级管理员 NOT NULL |
| email         | TEXT    | 邮箱（加密存储），用于通知与找回                              |
| phone         | TEXT    | 手机号（加密存储）                                     |
| status        | INTEGER | 状态：1 启用 / 0 停用，默认 1                           |
| created_at / updated_at | TEXT | ISO-8601，NOT NULL                        |

### 4.2 待补的组织模型实体（FR-U01/U04，未设计）

## 六、考证刷题内容层表（2026-10-09 设计，已实现）

权威定义：teaching-training 工作区 `webapp/schema.py`（追加于六表块之后）与 `src/models.py` 对应数据类。**与六表的差异**：内容为全局共享，不做 `college` 隔离（证书/考纲服务所有院校）；个人数据（个人考试日、学生目标）经 `student_info` 外键间接归属，机构隔离复查在服务层沿学生归属进行。

| 表 | 作用 | 关键列与约束 |
| - | --- | --- |
| `certificate` | 证书目录（FR-K01） | `code UNIQUE`、`subjects_json`（科目清单）、`source_ref`（依据说明）、`active` |
| `exam_date` | 考试日期（FR-K02） | `certificate_id` 外键、`date_type`（official/expected/personal，CHECK）、`student_id` 外键（CHECK：personal 必挂学生）、`created_by` 外键（内置数据为空）；索引 `(certificate_id, date_type, exam_date)` |
| `knowledge_point` | 考纲知识点（FR-K03） | `UNIQUE(certificate_id, code)`、`parent_id` 自引用外键（层级树）、`source_ref`/`outline_version`（考纲依据与版本） |
| `knowledge_point_link` | 知识点双向关联（FR-K05） | `target_type`（rule/task/question，CHECK）+ `target_id`；`UNIQUE(knowledge_point_id, target_type, target_id)`；反向索引 `(target_type, target_id)` |
| `knowledge_point_mark` | 三类标注（FR-K04） | `mark_type`（high_freq/risk_context/error_prone，CHECK）、`level`、`basis_ref`/`basis_version`（依据；考证高频类由服务层强制） |
| `student_goal` | 学生考证目标（FR-K02） | `student_id`/`certificate_id` 外键、`planned_date`、`official_date_id` 外键、`status`（active/paused/achieved/archived，CHECK）；**部分唯一索引**：同学生同证书仅一个 `active` 目标 |

倒计时取值口径（服务层）：优先 `student_goal.official_date_id` 指向的官方日期，无则用 `planned_date`；均空时仅展示已选证书，不虚构日期。
