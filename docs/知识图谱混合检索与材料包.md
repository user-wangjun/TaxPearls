# 知识图谱本地混合检索与 AI 材料包

本轮根据《知识图谱本地混合检索与AI材料包_开发实施计划_v1.0》完成工程实现和本地验收，代码归属 `policy-knowledge-graph`。用户明确允许复用此前采集的数据并编纂测试数据，因此采用 20 份标记为虚构的政策场景建立独立工程预期集，另复用 5 份真实来源快照验证解析、检索和溯源。没有把合成预期集称为税务人员审核过的标准答案。

## 用户流程与阶段交付

企业任务保存材料后，在“知识图谱 → 政策检索与检查材料包”选择企业任务、检查项目和地区，系统按保存的期间从标准记录取数。先展示本地检索结果、程序条件结果、条款原文、来源记录、必要例外、修改关系和缺口；本地评测通过且模型配置有效后，可请求 AI 辅助分析。结果和输入版本保存在该企业任务的加密版本中，支持 JSON 材料包导出。

| 计划阶段 | 已完成行为 | 验收边界 |
| --- | --- | --- |
| P0 数据与基线 | 沿用 Policy、Clause、TaxRule、Entity、Metric、Condition、Exception、Relationship；20 份合成政策、13 个明确预期案例 | 合成库只允许在没有业务账号、审计、既有政策的隔离库创建；不自动灌入业务库 |
| P1 图关系 | 已审核规则引导 1–2 跳检索，保留路径；条件、例外及原文来源强制补齐；修改关系按依赖闭包展开 | 不通过 Policy 枢纽泛取整份文件；候选关系标待复核；闭包有访问集合防止环路 |
| P2 关键词 | SQLite FTS5 trigram、中文词组与有界三元片段；两字词使用转义的 LIKE 兜底；触发器同步增改删 | 词面未命中如实返回空，不伪造成语义检索成功 |
| P3 本地语义 | BGE 中文模型真实 ONNX CPU 推理、512 维归一化向量及 FAISS IndexIDMap2；长条款分块完整覆盖；内容/模型版本与稳定向量 ID 对应 | 无模型返回 not_ready；检索不会下载模型或调用外部 LLM；离线测试缺模型会跳过模型单测，但评测门槛仍失败 |
| P4 融合与适用 | 每路默认 20 候选、RRF k=60、复核默认 30；必要依据不受截断；条款级期间、地区、修改/废止核查 | 空终止日期不推定永久有效；跨生效日返回分段；部分修改不推断整份失效；低相关候选记录过滤原因 |
| P5 材料包 | 完整事实和来源、指标定义、逻辑、条件/例外、政策版本、原文、变化、缺口、检索过程与内容哈希 | UTF-8 字节数作为保守 token 上界，默认软预算 6000；按完整条款拆包，必要上下文重复保留；无法容纳时完整保留并转复核 |
| P6 离线门槛 | K01–K12 加三材料口径 K13，真实本地模型参与，逐项输出召回、精度、例外、变化及引用指标 | 100% 是该合成预期集的结果，不代表真实政策泛化效果 |
| P7 AI 与版本 | 只发送编号材料包；回查规则/条款/来源 ID、金额、日期、类型与程序结果；异常输出降级；内容缓存、防重复调用、CAS 保存和按依赖标记过期；上传任务直达核查并生成冻结检查报告 | 不自动产生法律认定或改变旧审计 Finding；新任务支持网页/PDF/JSON 报告及历史版本，完整编审工作台仍未实现 |

指标当前支持已有标准数据的 direct、sum、count。派生计算代码不直接执行；跨材料比较如无已复核调整口径保留 UNKNOWN。会计收入、申报销售额、发票金额存在差异时，不直接下税务结论。候选维护、原件核实和规则批准接口见 [Schema 实施说明](税务知识图谱Schema_v1.md)。

## 依赖与复现

在已安装项目依赖的 Python 环境中补装可选本地检索依赖：

```powershell
python -m pip install -r requirements-knowledge.txt
python scripts/prepare_kg_model.py
```

准备脚本是显式联网操作。模型默认保存在当前进程的 `%LOCALAPPDATA%/TaxPearls/models/bge-small-zh-v1.5-onnx`，可用 `TAXPEARLS_KG_MODEL_DIR` 指定其他目录。Codex 环境的 LOCALAPPDATA 可能被 Windows 应用包重定向，应以准备脚本输出为准。模型不进入 Git，不下载可执行模型代码；运行时逐项校验本地 manifest 中的哈希。

使用 [BAAI/bge-small-zh-v1.5](https://huggingface.co/BAAI/bge-small-zh-v1.5) 的 MIT 许可模型，固定上游修订 `7999e1d3359715c523056ef9478215996d62a620`，固定 [ONNX 导出](https://huggingface.co/onnx-community/bge-small-zh-v1.5-ONNX) 修订 `9507db33464b5da99a532ac26b2a251767cbc62b`。ONNX 及其外部权重有代码内固定 SHA-256；tokenizer、配置和上游说明的哈希写入本地 manifest。

以下命令在本工作区根运行；新建验收库拒绝覆盖已存在文件，已建库可直接重新索引/评测：

```powershell
python -m src.kg_retrieval.cli seed-demo --db output/kg-retrieval/tax_kg.db --originals output/kg-retrieval/originals --offline
python -m src.kg_retrieval.cli build-index --db output/kg-retrieval/tax_kg.db --output output/kg-retrieval/vectors --offline
python -m src.kg_retrieval.cli evaluate --db output/kg-retrieval/tax_kg.db --cases tests/fixtures/kg_retrieval/gold_cases.json --output output/kg-retrieval/retrieval_report.json --offline
python -m src.kg_retrieval.cli retrieve --db output/kg-retrieval/tax_kg.db --cases tests/fixtures/kg_retrieval/gold_cases.json --case K13 --output output/kg-retrieval/K13.json --offline
```

`import-corpus` 支持 `--manifest 来源清单.json --document-id 文档ID`（可重复）、`--db`、`--originals`、`--output`，复用此前原件及文本哈希。识别“第N条”和“一、”章节；无法可靠分条时保留“未分条正文”并标 needs_review。发文日期只取明确 publish_date，不把落款日期冒作发布日期。

数据库增加辅助 `kg_clause_fts`、FTS 触发器、`kg_clause_vectors`；八类领域表保持兼容。向量缓存随条款内容及版本增量更新，FAISS 导出文件名带索引哈希，映射 JSON 记录模型、条款、分块、内容与索引文件校验值。索引导出不替代 SQLite 持久映射。

新增接口：GET `/api/knowledge/checks`、GET `/api/knowledge/retrieval/status`、POST `/api/knowledge/retrieve`。企业模式只接受 task_id、expected_revision、项目/地区/主题等控制参数，事实从当前授权任务读取。客户端不能在此接口提交任意企业金额。保存前再次鉴权及比较版本；资料变化时仅将实际依赖指标变化的旧检查标记 stale，重新检索时按完整内容决定是否复用。旧版本保留。

AI 门槛读取当前工作区 `output/kg-retrieval/retrieval_report.json`，核对全部案例、门槛指标、实现指纹和包内模型指纹。检索、适用核查或材料包代码改变后须重新离线评测。AI 使用现有 knowledge 用途配置及密钥优先级；本轮只在进程中读取原项目 `.env` 的 AI 项，不复制密钥文件或把密钥写入产物。

## 上传、核查与报告衔接补充验收（2026-10-15）

上传页创建核心资料任务并保存核对后，点击“继续核查”直接进入知识图谱中的材料包，自动带入同一任务、企业与期间。未保存口径编辑时阻止跳转。已经保存的检查可重新查看；“返回资料补充”直接打开原任务，无需新建或再次选择企业。任务资料齐备状态与项目核查状态分别展示，不将个别项目完成当成全部检查通过。

本地核查或 AI 分析保存后，页面自动生成本任务的企业税务核查报告；也可手动生成。报告包括已保存项目的汇总、程序条件、例外、缺口、完整政策依据、AI 校验结果及原表取数位置，提供网页查看、PDF、JSON。未运行项目明确不作结论，未知与排除分别统计；AI 输出失效时显示待复核，不伪造风险或通过。报告保留任务版本和材料包指纹，后续资料变化不会改写旧版本。

新增辅助表 `core_tax_reports`，不更改公共知识图谱的八类领域表。HTML/快照和首次导出的 PDF 使用现有材料密钥与机构、任务、版本绑定加密保存。归档事务内重新鉴权并比对任务版本、现有材料和政策内容；材料、政策或规则已变化时，拒绝将旧结果当作当前报告。模板变更形成新版本。PDF 复用首次生成的字节，渲染完成后再次检查当前权限。既有历史审计归档继续保持原样，新的 TaxRule 结果不强行转换成旧 YAML 执行器的 hit/pass。

| 新接口 | 行为 |
| --- | --- |
| POST `/api/enterprise/input-tasks/{task_id}/recheck` | 依据保存项目逐一比对最新材料与政策；只替换受影响结果，复用未变化结果和已保存 AI，不自动付费重发；更新任务汇总 |
| GET `/api/enterprise/input-tasks/{task_id}/reports` | 当前权限下列出冻结报告版本 |
| POST `/api/enterprise/input-tasks/{task_id}/reports` | 使用 expected_revision 归档；相同内容和模板复用最近版本；未检查或旧结果已失效时拒绝 |
| GET `/api/enterprise/input-tasks/{task_id}/reports/{version}?format=html\|pdf\|json` | 读取指定版本、按需生成并缓存 PDF，或导出完整报告数据 |

补传、排除或重新核对资料时，受影响项目标记 stale，汇总同步改为待复核。点击“重检受影响项目（本地）”后，变化项目重新取数与核对，未变化项目保留原版本；变化项目原有 AI 不沿用，须明确点击 AI 分析才发起新请求。页面随后自动更新报告版本。
