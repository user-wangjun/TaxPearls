# 税海拾珠 · 输入输出与业务逻辑

## 当前 Web 流程

```text
登录 → 上传材料 → 核对主体与指标 → YAML 规则求值 → 证据卡 → HTML / A4 PDF
```

Web 入口为 `python -m webapp`，命令行入口为 `main.py`。页面提供工作台、材料核对、审计详情与基础管理；审计快照保存到 SQLite。

## 输入约定

| 工作表   | 内容                                |
| ----- | --------------------------------- |
| 企业信息  | 企业名称、纳税人识别号、所属行业、所属期              |
| 科目余额表 | 科目编码、科目名称、期初余额、本期借方、本期贷方、期末余额     |
| 增值税申报 | 项目、金额；包括销售额、销项税额、进项税额、应纳税额和期末留抵税额 |
| 填表说明  | 仿真样例说明，解析时不读取                     |

使用 `samples/样例企业-审计材料.xlsx` 的表头。科目到指标的映射位于 `src/config.py`；未知科目不参与聚合。每项标准指标记录数值、来源和计算说明。

## 多源材料与业务勾稽

- 多期间：利润表发生额按期间归集，完整月份可生成滚动 12 月指标；资产余额按期点比较，不跨月相加。
- 数电发票：解析 XML 或标准发票明细，校验企业、期间、票号、红字及作废状态。票面税额不能直接当作申报表或账面税额。
- 银行材料：解析银行流水，结合经复核的银行调节底稿形成收入口径；未复核、缺底稿或重复调节不自动计入。
- 人力记录：按人员身份、月份和有效状态去重，归集工资与社保等人数口径；人数缺项不推测。
- 合同履约：通过合同台账、履约记录和四流勾稽表关联合同、发票、银行流水及履约单据，校验金额、期间与复核状态。

企业材料按单企业、单主期间持久化分析和确认。原件留存上传字节与指纹，补传、修正和重检形成新版本；兼容教学草稿仍在进程内存中。

Excel 与多文件解析共用工作簿、期间和输入错误处理。比较指标要求期间完整且口径可比；发生额按覆盖期间归集，时点余额只按对应时点读取。AI 提取结果作为候选数据进入校验，不自动替代缺失来源或人工确认。公共快照序列化工具保留数值、来源和关联关系，供报告与业务流程复用；读取已保存的审计快照不重新执行规则。

## 材料来源与归集口径

标准账表、来源适配与人工候选核对是不同入口。标准模板按约定表头读取，来源适配只覆盖明确支持的格式；不能因为后缀为 Excel、XML 或 PDF 就宣称内容均可识别。

| 来源              | 归属、期间与金额口径                                    | 缺项及冲突处理                                       |
| --------------- | --------------------------------------------- | --------------------------------------------- |
| 发票电子数据          | 区分买卖双方与被检测企业，保留票号、单据日期、红字和作废状态；票面税额不等于账面或申报税额 | 核对重复票与来源，不把同一发票跨文件重复计入；未知结构与无法核对的归属须复核        |
| 银行流水与调节底稿       | 区分本方账户、交易对方与业务期间；现金收支只有结合经复核的调节依据才能形成相应收入口径   | 缺底稿、重复调节或未复核记录不能自动计入；有稳定流水编号时据此去重，不凭金额相同认定重复  |
| 利润表、资产负债表、现金流量表 | 金额、单位、报表时点、发生期间与来源位置分别保留；发生额按覆盖期间归集，时点余额不跨期累加 | 不把单位不明、期间不全或不可比的值用于趋势；冲突不自动覆盖或相加              |
| 人力与合同履约材料       | 保留人员/合同/记录编号、有效状态、实际期间与依据；工资、社保、履约、发票和资金分别归集  | 缺项、未复核与重复记录保持可见，不猜测缺失金额，不把缺证据判为一致             |
| PDF 与非标准候选      | 可识别文本与模型输出均为候选，保留原文位置、金额和单位，人工核对后使用           | 扫描、读取失败、字段不存在与单位未知分别处理；模型不能补造事实或以票面值代替申报/账面指标 |

材料业务期间、单据日期、报表时点、导出时间、上传时间用途不同，不能相互替代。历史参考保留实际期间，不混入本期金额；与当前期间不匹配的材料须明确用途或排除。公开单组流程保存材料用途、分析与确认版本，原件使用独立密钥认证加密留存。

## 企业材料核对与输入分析

企业自用与机构多客户管理共用单组检测目标：一家被检测企业、一个主期间、多份文件。企业名称、税号和主期间起止日须明确；行业缺失如实提示，不编造行业。可识别且无歧义时从材料预填，不能用文件名、文件修改时间或上传时间替代企业归属或业务期间。

每份文件选择本期、历史参考或排除。历史参考必须属于同企业、明确实际期间且早于主期间，只进入支持的期间序列，不替换本期账表金额。原材料税号冲突、归属无法核对或本期期间不符仍须处理，手改企业字段不能消除冲突。

分析只检查输入完整性、冲突与规则是否具备可计算条件，不执行阈值判断或关联方风险结论。反馈分为必须处理、缺失但可继续、建议补充，并附涉及文件、影响和处理建议。读取失败不当成字段不存在，缺项不补零，零值仍是有效输入；分母为零或基期不足时列出不能执行的检查。

标准表数值修正仅接受允许的单元格，保留原值、修正值、来源位置和修正标记；候选账表重新解析与计算，原件不改写。非标准候选指标须人工核对，不允许用任意浏览器数据伪装服务端原文。字段修改不强制填写理由；操作人、操作时间与字段前后值由持久化版本和操作日志记录。

本地与 AI 提取保留材料指纹、来源位置、提取程序及依赖指纹。AI 请求还记录所请求模型、提示和结构指纹、请求次数及成功/失败状态；提供方未返回确切模型修订版时保持未知，不把请求模型名当成实际修订版。记录不包含密钥或环境变量，运行时间用于描述当次提取过程。

上述输入分析与修正已接入公开接口和单组页面。确认绑定企业、期间、文件、用途、修改和可执行范围快照；材料变化后重新分析和确认，补传重检形成新版本并保留先前结果。原件认证加密留存，访问控制和删除影响提示已接入，真实来源与生产密钥保管仍须单独验证。

## 规则与判定

| 求值类型            | 判定口径                      |
| --------------- | ------------------------- |
| deviation       | 两指标绝对差额除以比较基数的绝对值，超过阈值时命中 |
| amount_mismatch | 两指标绝对差额超过容差时命中            |
| ratio_range     | 两指标比值超出闭区间时命中             |

规则定义包含 ID、风险类型、等级、逻辑、证据指标、依据与建议。当前加载 R-001 至 R-024。补充指标使用指标、数值、来源、所属期和口径说明五列；人力数据可由人力记录表按人员身份、月份和状态归集，缺少人数时 R-004 显示未执行。

结果区分命中、通过、未执行。缺少必需指标时说明缺项；未执行不能计入通过。

## 输出约定

- 企业、期间、报告编号与生成日期。
- 命中、通过、未执行数量与规则清单。
- 证据卡：指标值、来源、计算过程、阈值、依据与建议。
- 未执行项及原因、报告声明、编制与复核栏。

HTML 默认写入 `output/report.html`，PDF 默认写入 `output/`。生成日期描述报告出具时间，输入所属期描述材料业务期间。

## 教学输入与输出

已有班级作业使用发布时冻结的仿真材料与标准答案，输出学生答案、命中/漏检/误报、计分依据及教师批改。真实企业原件和报告不能因教学身份而放宽权限或转作教具。

学情统计使用当前有效名册与最新有效提交，未交、损坏和未执行分别列示。个人画像只反映授权范围内的作业表现，口径变化须标明；错题本的独立重练保存订正结果，不修改原作业成绩、教师批改及班级统计。新正式提交与错题记录同事务保存；已有提交通过明确操作幂等纳入，材料或评分口径变化时暂停重练。具体验收条件见 [PRD](02-产品需求文档.md) 的教学章节。

## 验证方法

使用仿真材料核对指标、规则结果和证据来源；构造缺项和阈值边界，确认执行状态；生成 HTML / PDF 并检查中文、页码和内容。检查输入文件不存在、缺工作表与规则目录无效时的错误提示和退出码。

## 企业材料版本与结果追溯

上传后先分析主体、期间、来源冲突和检查可执行范围，确认前不生成正式风险结论。确认绑定服务端保存的分析版本及规则定义，输入变化后重新分析、确认；同一版本重复确认返回已有结果。

补传追加原件及材料来源，保留原有用户修正。审计结果和冻结报告关联当时确认的材料快照，查看已有结果不以最新材料替换旧输入。原件下载、确认材料查看和删除复查当前机构、角色及客户归属，并记录操作。

请求操作记录区分已开始、已提交、失败和未知响应。重启不把未完成请求自动认定失败；响应中断后先核对已有结果和操作状态，避免重复执行。

## 数据使用

当前样例由脚本生成，仅用于开发和教学演示。真实业务上线须完成访问控制、敏感信息保护、审计日志、加密备份和环境隔离；当前已有基础登录、角色权限和业务日志；企业原件及材料版本载荷、当前客户标识和审计证据、归档报告、日志详情及教学提交已认证加密留存，生产隔离尚待接入；本地认证加密备份与恢复已实现，生产策略仍须验证。

## 账号与运行数据

登录采用限频和强口令校验。邮箱验证码、邮件链接和重置凭证限时、限次并绑定发起浏览器；链接需通过明确操作兑换，成功重置后注销已有会话。密码登录默认使用邮箱，同时支持用户名；优先匹配绑定邮箱，停用的邮箱账号不会回退到其他同名用户名账号。未勾选保持登录时会话为 12 小时，勾选后固定 30 天，Cookie 与数据库会话同步到期且不自动续期。退出只撤销当前会话，密码重置撤销该账号全部会话；密码不写入浏览器存储。

业务数据库通过 SQLite 在线备份接口在内存中生成一致性快照，并以 AES-256-GCM 认证加密后保存。恢复须停止服务，恢复前保留经过验证的加密安全副本。保留期由操作者明确选择，工具支持到期预览和单文件销毁回执；不自动删除备份。密钥只从进程环境读取，备份与密钥分别保管且不随代码提交。明文兼容命令须显式允许。

业务敏感字段使用独立的 `TAXPEARLS_FIELD_KEY`（32 字节随机密钥的 Base64），加密绑定表、列与记录身份；机构内等值查询使用带密钥的索引，索引不用于授权。缺失或错误密钥拒绝访问，已加密字段的明文或跨记录替换拒绝写入。已有数据库须停服执行离线迁移与压缩；认证加密恢复先验证字段内容，再替换目标。实际命令见 [运行说明](05-部署备份恢复与回滚.md)。

## 协作、版本与关联材料

邀请开户使用邮箱所有权凭证及校验题，注册时在同一事务中核销邀请、检查席位并创建机构账号。平台管理机构配额，机构管理员管理本机构成员与角色限定的邀请链接；邀请可刷新和停用，域名策略由机构明确配置。真实邮件发送须配置已验证地址和密钥。

标准关联材料由主体、关联关系、关联交易三张表构成。记录包含稳定编号、日期、复核状态与依据；图规则与条件规则独立求值，共同进入审计结果。规则版本按材料业务期间选择，日期不明或跨越版本区间时要求补全或拆期。

审计保存后按接收人范围生成站内通知；邮件只发送规则摘要，不含原件或财务明细。本人明确同意邮件订阅且后端启用摘要邮件开关后才尝试发送；中断或未知响应保持可追溯状态，不盲目重复发送。投递按渠道独立保存冻结摘要与幂等键；绑定基础只接受可信服务端适配器验证的身份，并要求原登录会话确认。审计先完成保存，通知创建失败不回滚审计结果。

## 高校实训模块业务逻辑

面向高校客户的代码实训教学能力，需求定义见 [产品需求文档](02-产品需求文档.md) 第十一节，差距判断见 [高校端与代码实训差距分析](04-高校端与代码实训差距分析.md)。

用户角色：

| 角色      | 职责                                             |
| ------- | ---------------------------------------------- |
| 高校管理员 | 创建课程与班级，录入并发布代码实训任务，查看任务与评分报告 |
| 学生      | 查看所属班级的实训任务，提交源代码，查看本人评分报告   |

整体业务流程：

```text
管理员创建课程 → 创建班级 → 发布代码实训任务 → 学生查看任务、提交代码 → 系统沙箱运行代码 → 比对测试用例自动评分 → 师生查看评分报告
```

- 课程绑定名称、学期标注与任课教师，同一课程可多班平行开课；班级沿用现有「机构 → 班级」模型，绑定课程、任课教师与学生名册。
- 实训任务在课程班级下创建，包含题面、语言、时限与内存限制、测试用例、评分标准与截止时间；发布与名单沿用班级作业框架。
- 学生在截止时间内查看任务并提交源代码，可多次提交；每次提交独立存档，保留代码内容、提交时间与判题结果版本。
- 系统在沙箱中隔离运行提交的代码：单线程串行执行，一次一个判题任务；禁用网络，限制 CPU、内存、时间与文件系统写入，超限终止并归因。
- 判题逐测试用例运行并比对输出，支持浮点容差与空白容忍，按用例权重计算部分得分；编译错误、运行错误与超时分别归因。
- 判题结果作为客观事实来源回填现有评分框架，形成评分明细报告；师生按授权范围查看，评分标准可配置，教师调分留痕。

输入：

| 来源      | 内容                                                              |
| ------- | --------------------------------------------------------------- |
| 高校管理员 | 课程、班级、实训任务与测试用例（输入、期望输出、权重），以及评分标准与截止时间 |
| 学生      | 源代码提交，语言与运行限制随任务约定                                    |

输出：

- 任务列表：按课程与班级展示已发布实训任务、截止时间与提交情况。
- 代码运行日志：每次提交在沙箱内的编译与逐用例执行记录，含超限与错误归因。
- 自动评分明细报告：每个测试用例的通过 / 失败、得分与归因可展开核对，每分必有所据。

约束：

- 复用现有登录鉴权、作业存储模块：高校管理员与学生挂入现有角色框架，读写归属复查沿用现有模式；任务发布、提交与名单沿用班级作业框架，不新建账号体系，不另建作业系统；代码提交与判题记录按现有敏感字段要求加密留存。
- 沙箱单线程执行：判题沙箱串行处理提交，一次只运行一个判题任务；隔离、资源限额与单线程串行为上线前置条件，判题日志全程留痕。判题沙箱是独立于规则引擎的全新执行面，规则引擎不执行学生代码。
- 教学只使用仿真 / 教学数据，编程题与测试数据同样适用现有红线。

二期预留功能不进入上述业务主流程，仅作未来规划：师生批量导入（Excel 名单建号与账号班级批量绑定）、判题任务并发队列调度（排队、失败重试与状态机）、代码查重（班内与跨班同题比对）与代码质量规范评分（lint、编码规范、复杂度）。完整范围见 [产品需求文档](02-产品需求文档.md) 第十一节。
