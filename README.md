```bash

python -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements.txt

# 2. 生成仿真样例材料（首次运行需要）
.venv/Scripts/python.exe scripts/make_sample.py

# 3. 命令行端到端：材料 → 规则判定 → PDF 报告
.venv/Scripts/python.exe main.py

# 4. Web 端证据链页面（推荐）：浏览器上传 → 风险清单 → 证据卡 → 导出 PDF

# 然后打开 http://127.0.0.1:8000
# 首次打开会要求创建平台管理员；系统不提供默认账号或硬编码密码
```

## 输入：审计材料

Web 工作台支持一次选择多份 `.xlsx`、`.xml`、`.pdf`，也支持 `.zip` 文件包。上传后先进入材料核对页，再执行审计。

- **同一企业、同一核对期间**：可以把科目余额表 Excel、申报表 PDF、利润表、数电发票 XML/Excel、来源银行流水、银行调节底稿、人力记录、合同台账、履约记录和四流勾稽等分开的材料合并为一次审计。企业和期间必须一致，缺少的信息可在核对页补充；同名指标冲突时阻止合并。发票按票号、银行流水按唯一流水号、人力记录按人员哈希/类型/月、合同及勾稽记录按各自编号跨文件去重。
- **不同企业或不同期间**：选择“每个文件分别审计”，逐份生成报告和历史记录。有效文件可独立完成，错误文件单独显示原因；一次提交成功后再次提交返回原结果，避免重复建档。
- **文字 PDF**：配置 AI 后，按页发送文字及可选页面图片，由模型提取标准指标、原始数值、单位、原文引用与疑点；后端校验 JSON、白名单指标、页码与文本引用，进行确定性的单位换算。未配置或选择本地模式时使用常规文字/表格解析。结果可修改、移除或补录，须确认企业、期间及口径。
- **扫描 PDF**：启用支持图像输入的模型及 `TAXPEARLS_AI_VISION=1` 后，本地把页面转成图片交给视觉模型提取；图片引用无法通过本地文字匹配验证，会标为需对照原图核对。未配置视觉能力时明确提示，仍可手工补录。真实识别效果须用实际模型验证。
- **来源追溯**：指标保留文件名、内容指纹及工作表/页码，PDF 同时记录人工核对和识别原值。缺失数据不会变成零，依赖缺失指标的规则显示“未执行”。
- **容量**：每次最多 20 个文件，单文件或 ZIP ≤ 10MB，上传及解压后合计 ≤ 50MB，单份 PDF ≤ 50 页。不支持加密/嵌套 ZIP。原始材料只在内存中处理，核对任务有效期 10 分钟；持久化的是规范化证据与审计结果。当前核对草稿属于单进程内存，多进程部署需增加共享草稿存储或会话粘滞。

命令行和兼容接口 `/api/audit` 仍使用完整标准 Excel（三张必需工作表）。Web 多材料入口 `/api/materials/preview` → `/api/materials/audit` 也可读取下表中的独立工作表，标准 Excel 工作表名及列头须满足下表格式。完全不含标准工作表名的 Excel 可交给 AI，保留工作表名与单元格位置；包含公式或标准表校验失败时直接报错，AI 不绕过这些校验：

| 工作表 | 内容 |
| --- | --- |
| `企业信息` | 企业名称、纳税人识别号、所属行业、所属期 |
| `科目余额表` | 科目编码、科目名称、期初余额、本期借方、本期贷方、期末余额 |
| `增值税申报` | 销售额、销项税额、进项税额、应纳税额、期末留抵税额 |
| `填表说明` | 供填表人阅读，系统不读取 |
| `补充指标`（可选） | 指标 / 数值 / 来源 / 所属期 / 口径说明；用于报表、历史、银行、发票、社保和参考值的人工整理输入 |
| `利润表` / `资产负债表` / `现金流量表`（可选） | `项目 / 本期金额`；自动转为带表名前缀的标准指标 |
| `历史指标`（可选） | 明确实际期间的 `历史.*` / `年度.*` 指标，支撑同比与连续年度规则 |
| `发票明细`（可选） | 销项/采购、正常/红字/作废结构化明细；也支持财政部数电发票 XBRL XML 和来源 Excel 表头映射，自动汇总不含税/税额净额及明确确认的本期抵扣税额 |
| 来源银行 Excel / `银行流水`（可选） | 建设银行公开字段口径及通用流水号、日期、借贷方/收支金额、摘要表头；只汇总原始收支，不直接作为收入 |
| `银行调节`（可选） | `调节编号 / 流水号 / 分类 / 权责所属期 / 本期不含税收入 / 调节金额 / 调节方向 / 底稿编号 / 复核状态 / 说明`；全部收入逐笔复核后才生成 R-015 输入 |
| `人力记录`（可选） | `记录类型 / 姓名 / 证件号码 / 所属月 / 状态 / 金额 / 来源`；个税、社保、公积金按人按月去重，生成 R-004 人数及对应金额指标；姓名和原始证件号不持久化 |
| `合同台账`（可选） | `合同编号 / 合同类型 / 对方名称 / 签订日期 / 合同含税金额 / 履约起始日 / 履约结束日 / 复核状态 / 底稿编号 / 说明`；允许先登记、后补流转证据 |
| `履约记录`（可选） | `履约单据号 / 合同编号 / 履约日期 / 履约类型 / 含税金额 / 复核状态 / 底稿编号 / 说明`；支持发货、收货、服务验收和其他履约 |
| `四流勾稽`（可选） | `勾稽编号 / 合同编号 / 发票号码 / 银行流水号 / 履约单据号 / 勾稽含税金额 / 复核状态 / 底稿编号 / 说明`；合同、正常发票、方向一致资金、已复核履约均存在且分摊金额完全覆盖合同时才标记四流完整 |

**标准化**：各财务软件科目编码口径不同，统一在 `src/config.py` 的 `ACCOUNT_MAP` 中映射为标准指标。
科目编码不在映射表覆盖范围内的，该科目不参与计算，不报错。
多科目聚合要求列出的科目全部存在，无发生额也应显式提供零行；缺科目或空值不当零处理。
补充指标的所属期须与企业信息一致，历史实际期间写入口径说明；不得覆盖原始表的基础指标。

## AI 提取与部署配置

根目录 `.env` 已准备好，填写 `TAXPEARLS_AI_API_KEY` 即可使用默认官方地址；使用第三方网关时同时填写 `TAXPEARLS_AI_BASE_URL`。密钥仅在后端读取，`.env` 被 Git 和 Docker 构建上下文排除。进程环境变量覆盖 `.env`，修改后须重启服务。

```dotenv
TAXPEARLS_AI_ENABLED=1
TAXPEARLS_AI_BASE_URL=https://api.deepseek.com
TAXPEARLS_AI_API_KEY=填写密钥
TAXPEARLS_AI_MODEL=ds-v4.1f
TAXPEARLS_AI_VISION=1
```

DeepSeek 官方文档当前把 V4.1 Flash 的调用名写为 `deepseek-flash`：本项目仅在官方域名下把 `ds-v4.1f` 映射为该名称；第三方网关原样使用配置的模型名。协议采用 `POST /chat/completions`、Bearer 密钥、JSON 输出和 `image_url` 图片输入。参见 [官方调用说明](https://api-docs.deepseek.com/) 与 [请求契约](https://api-docs.deepseek.com/api/create-chat-completion/)。

页面提供自动 / AI / 仅本地三种模式，并显示配置状态。标准 Excel 直接解析；AI 用于 PDF 与非标准 Excel。AI 任务在后台执行，浏览器查询进度，避免把长时间提取塞进单个上传响应。每批默认最多 20 次调用、300 秒，单文件最多 12 页/工作表，每次最多 3 页；这些限额可在 `.env` 调整。失败、截断、限流和格式错误不会自动重试，也不会标成 AI 成功；PDF 保留可用的本地候选，非标准 Excel 显示错误。AI 没有通过验收的原值会留空或标注疑点，模型不参与风险判定。

审计详情中的“AI 白话解读”仅用于已经命中的 Finding。后端只发送该审计快照中的规则、确定性结论、计算、阈值、证据来源、法条和建议，并强制模型返回 `hit` 与同一规则 ID；改判、错引、格式错误和非命中请求都会被拒绝。通过校验的解读按证据 SHA-256 持久化复用，界面始终把“规则引擎结论已锁定”与模型文字分开显示。

“AI 总体评价与处理建议”只汇总当前审计已冻结的 Finding。命中、通过、未执行数量由服务端锁定，每段必须引用当前审计中的具体规则；未知引用、空引用、统计不一致和模型新增事实都会被拒绝。通过校验的内容按证据 SHA-256 持久化，并同步进入审计详情、HTML 和 PDF 报告。

部署前填好 `.env`，反向代理 HTTPS 时设 `TAXPEARLS_COOKIE_SECURE=1`。在部署主机运行：

```bash
docker compose config --quiet
docker compose up -d --build
```

`compose.yaml` 把服务绑定到主机 `127.0.0.1:8000`，由外部反向代理提供 HTTPS；数据库存入 `taxpearls-data` 卷。镜像包含 Chromium 与中文字体，供报告 PDF 导出。健康检查为 `/healthz`。服务必须先保持**单进程、单副本**，因为待核对材料与 AI 任务存于进程内存；重启会丢失进行中的任务，已保存审计不受影响。不要使用 `docker compose down -v` 删除数据卷。

当前验证区分：命中 Finding 的文字解读和基于全量 Finding 的总体结论均已用当前配置的真实 Provider 验收；PDF/非标准 Excel 的真实提取准确性仍须按材料另行评估。Linux 镜像构建、生产 TLS、数据库备份恢复和镜像回滚均已完成隔离环境验收。部署到已有系统时，挂载原数据库或迁移原数据卷，不能把空卷误认为历史记录丢失。具体命令、校验清单和回滚步骤见 [部署、备份恢复与回滚](docs/05-部署备份恢复与回滚.md)。

## 输出：审计报告

A4 PDF，按内容动态分页：

1. **封面** —— 被审计单位、审计期间、报告编号、出具日期
2. **审计概况 + 结论摘要 + 规则执行清单** —— 含命中/通过/未执行统计；生成过受约束的 AI 总体结论时，同时显示逐段来源规则
3. **风险事项明细** —— 每项风险一张证据卡
4. **检查通过事项 + 未能执行事项 + 报告声明** —— 含编制/复核签署栏

每张**证据卡**包含：

```
风险类型 / 命中规则 / 风险等级
计算过程        —— 完整算式与阈值
证据表          —— 项目 / 金额数值 / 取数来源（逐项标明数据从哪来）
法律依据        —— 具体法条
整改建议
```

## 规则库（YAML 声明式）

三种求值类型：

| type | 语义 |
| --- | --- |
| `deviation` | 相对偏离度：`\|left − right\| / \|right\| > threshold` |
| `amount_mismatch` | 绝对差额：`\|left − right\| > tolerance` |
| `ratio_range` | 比率区间：`numerator / denominator` 落在 `[min, max]` 之外 |
| `all`（组合） | 全部子条件同时命中，用于连续亏损且持续扩张；不属于第四类业务比对 |

比率和相对偏离的分母必须大于零，否则未执行；区间边界包含在通过范围内。
金额采用 Decimal，支持 `add/sub/mul/div/min/max` 白名单公式，证据必须覆盖全部公式依赖。

规则示例：

```yaml
id: R-001
version: '2.0'
name: 账面收入与增值税销售额差异
category: 内部勾稽
tax_type: 增值税
severity: high            # high / medium / low
scope: 同一主体、同期不含税口径；合法税会时间差须人工调节。
inputs:
  营业收入: 科目余额表6001和6051本期贷方发生额，均须提供。
  增值税.销售额: 增值税申报工作表销售额栏。
logic:
  type: deviation
  left: 营业收入
  right: 增值税.销售额
  threshold: 0.10
evidence: [营业收入, 增值税.销售额]
legal_basis:
  - 《中华人民共和国税收征收管理法》第二十五条：如实申报义务。
references:
  - https://12366.chinatax.gov.cn/bzds/120/120-1-4.html
threshold_basis: 10%为教学预警参数，不是法定阈值。
suggestion: 编制收入调节表，复核未开票收入和税会时间差，确认错误后再更正。
```

设计要点：**每条规则自带 `evidence` 与 `legal_basis`**，使「可举证」成为规则的固有属性，
而非事后拼装。会计与教师可直接参与编写规则，无需写代码。

### 三种判定状态

| 状态 | 含义 |
| --- | --- |
| 命中 | 超出阈值，构成风险事项 |
| 通过 | 已执行，未发现异常 |
| **未执行** | **材料不足，未能执行。不构成「已通过」结论**，报告中单独列示 |

## 技术路线

**HTML + CSS → Chromium 打印 → PDF**，不使用 Word 转换。

中文排版的精细控制（字体、行距、首行缩进、表格数字对齐、分页不断行、页脚页码）
只有 CSS 能做得好；Word 自动化又慢又脆。通过 Playwright 驱动本机已安装的
Chrome（`channel="chrome"`），无需下载 Chromium。

排版规范：

- 正文思源宋体 10.5pt / 行距 1.75 / 首行缩进 2em / 两端对齐
- 标题黑体，与正文形成字形对比
- 表格金额使用等宽数字（`tabular-nums`）+ 右对齐，便于纵向比对
- 风险卡片 `break-inside: avoid`，绝不跨页断裂
- 页脚含报告编号与「第 X 页 / 共 Y 页」
