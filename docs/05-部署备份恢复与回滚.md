# TaxPearls 部署、备份恢复与回滚

本文是 FR-G08 的可执行运维基线。备份允许在线执行；恢复和版本回滚必须安排维护窗口。

登录限流同时按账号与客户端 IP 计数。反向代理部署时在 `.env` 的 `TAXPEARLS_TRUSTED_PROXY_IPS` 填写**代理连接应用时的固定源 IP**，并确保代理传递真实客户端 `X-Forwarded-For`；不要填写 `*` 或信任不受控来源。未正确配置时，应用会把代理视为同一个客户端 IP，导致其后的用户共享限流额度。服务保持单进程单副本；扩为多副本前须把限流状态迁至共享存储。

## 1. 数据库备份与校验

容器内数据库固定为 `/data/taxpearls.db`，命名卷为 `taxpearls-data`。备份使用 SQLite Online Backup API，不直接复制可能仍在 WAL 模式写入的数据库文件。

```bash
# 在线生成一致性备份及同名 .manifest.json 校验清单
docker compose exec -T taxpearls python scripts/ops_db.py backup \
  --database /data/taxpearls.db --output /data/backups/

# 将备份复制到宿主机或异地存储后再次校验
python scripts/ops_db.py verify backups/taxpearls-YYYYMMDDTHHMMSSffffffZ.sqlite3
```

清单包含 SHA-256、文件大小、SQLite `quick_check`、schema version 和每张业务表的记录数。缺少清单或任一项不一致时禁止恢复。

## 2. 恢复演练

先停止应用，保留反向代理的维护页。恢复命令会在目标数据库旁自动创建 `pre-restore` 安全备份；因此恢复结果不正确时仍可回到恢复前状态。

```bash
docker compose stop taxpearls

# 建议先在独立临时卷/目录验证，再操作正式卷
docker compose run --rm --no-deps taxpearls \
  python scripts/ops_db.py restore /data/backups/<backup>.sqlite3 \
  --database /data/taxpearls.db --yes

docker compose up -d --no-build
docker compose ps
curl --fail http://127.0.0.1:8000/healthz
```

恢复后必须抽查用户数、客户数、审计数、最新审计 ID，并用有权限账号登录查看历史审计。不能只以容器 `healthy` 代替数据验收。

如需撤销刚才的恢复，停止服务后将输出中的 `safety_backup` 作为下一次恢复源：

```bash
docker compose stop taxpearls
docker compose run --rm --no-deps taxpearls \
  python scripts/ops_db.py restore /data/taxpearls.db.pre-restore-<timestamp>.sqlite3 \
  --database /data/taxpearls.db --yes
docker compose up -d --no-build
```

## 3. 应用版本回滚

`compose.yaml` 的镜像名为 `taxpearls:${TAXPEARLS_IMAGE_TAG:-current}`。每次上线必须保留不可变版本标签，不能只保留 `latest/current`。

```bash
# 构建并记录发布版本
export RELEASE_TAG=20260923-01
docker build -t taxpearls:${RELEASE_TAG} .
docker image tag taxpearls:${RELEASE_TAG} taxpearls:current
docker compose up -d --no-build --force-recreate
curl --fail http://127.0.0.1:8000/healthz

# 回滚到已验证的旧镜像；数据结构不兼容时须先恢复对应数据库备份
export PREVIOUS_TAG=20260922-01
docker image tag taxpearls:${PREVIOUS_TAG} taxpearls:current
docker compose up -d --no-build --force-recreate
curl --fail http://127.0.0.1:8000/healthz
```

回滚验收必须同时确认：容器镜像 ID 已切回、健康检查通过、登录成功、历史审计可打开、HTML/PDF 报告可生成。失败时保留容器日志、镜像 ID、备份清单和演练时间。
