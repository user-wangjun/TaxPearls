# 税务知识图谱 Schema v1 实施状态

依据用户提供的《税海拾珠｜税务知识图谱 Schema v1（实施说明）》和 `taxpearls_knowledge_graph_v1.sql`，采用 SQLite 八类 Schema。公共政策知识不存储客户公司、发票或客户事实；企业上传资料仍使用已有业务记录结构，经 Metric 取数。

## 存储与版本

`webapp/policy_schema.sql` 保留所提供的八表基线：Policy、Clause、TaxRule、Entity、Metric、Condition、Exception、Relationship。`webapp/schema.py` 在创建 Store 时调用 `policy_graph.migrate()`，重复启动不重复建表，也不清空既有资料。

应用迁移在基线上补充版本字段，兼容已经用原 SQL 建好的数据库：

| 对象 | 补充字段与用途 |
| --- | --- |
| Policy / Clause | `version`、`supersedes_id`，保留原文与条款的不同版本 |
| TaxRule | `rule_code`、`version`、`fingerprint`、`execution_json`、`supersedes_id`，关联原规则身份和冻结的执行定义 |
| Metric | `logical_code`、`version`、`supersedes_id`，区分同名指标的不同口径 |

节点主键代表一个不可覆盖的内容版本。导入接口对相同 ID 只接受内容一致的重试，修改内容须用新 ID。审核状态通过专用审核操作改变；已审核规则不能再追加条件、例外或关系。这里的不可覆盖约束在应用服务执行，直接操作数据库仍须遵守版本约定。

现有 YAML 规则通过 `sync_rules()` 进入 TaxRule，保存原规则 ID、版本、完整快照及内容指纹；同一版本号但内容不同也保留为不同记录。原规则的 `legal_basis`、网址和教学参数不自动变成已核实 Policy/Clause 或法定标准。原审计执行继续使用 `src.engine`，历史图谱继续从审计冻结的 Finding 读取，公共知识更新不会重算或改写历史结果。

## 候选、校验与审核

- 导入按八类对象分组，在一个事务中完成；坏引用、未知字段、非法类型配对或条件组合使整包回滚。
- 条件只允许引用本规则的 Condition，组合为非空 AND/OR、单项 NOT 或 ref；限制嵌套深度，不执行表达式代码。
- Relationship 校验端点存在、关系类型及所属规则/政策；修订、废止和解释关系必须有不同端点、依据条款及生效日期。
- AI 单条款提取只生成候选，限制引用为本次对象和所给原文。数据入库前仍走同一套校验；没有自动审核或“五次一致后晋升”。
- 审核检查有效期、地区、条件来源、指标映射，以及引用原件的哈希、条款位置和人工复核状态。内部筛查参数不能以 `DERIVES_RULE` 冒充法定阈值。
- 平台管理员才可写公共候选或审核；写事务内重新检查账号权限，候选/审核变更与审计日志一起提交或回滚。

平台管理员的审核操作记录责任人，并不替代必要的税务专业复核。此轮没有把真实政策或真实风险规则自动批准为可正式使用。

## 指标与条件试算

`src/tax_conditions.py` 对已有 `core_materials.prepare()` 输出取数，保留来源记录 ID：

| 来源 | 已接入的口径约束 |
| --- | --- |
| VATDeclaration | 主附表、表名、行次、本期/累计列和完整税款所属期；旧单列格式可从 `field_sources.declared_value.source_label` 读取实际列名，不推定“本期数” |
| Invoice | 进销项、红字、作废口径、开票日期与资料完整状态；排除已标记重复来源，不自动计算红冲净额 |
| AccountBalanceRow | 科目字段、金额单位和完整会计期间；不自动按天拆分余额 |

当前支持 direct、sum、count。派生指标的计算函数须逐项接入受审核的程序注册表；未接入的 `derived` 或 `calculation_code` 会阻止审核，不执行 SQL/Python 文本。

金额使用 Decimal；汇总使用 64 位十进制精度。缺资料、单位不一致、企业/机构/任务不一致、匹配为空、直接取数有多个来源或期间不明确时，保留 UNKNOWN，不补零。当前不自动拼接跨月申报/余额指标；跨期口径需单独配置后接入。

条件结果为 TRUE / FALSE / UNKNOWN。例外未知或需要调整结果时转复核；exclude 是独立的排除状态，不伪造一个“检查通过”。规则、政策、条款、关系及主体需要覆盖完整所属期，当前范围不能证明时保留 UNKNOWN。

试算返回包含规则、条件、例外、指标定义、政策条款、关系、输入事实、期间与地区的快照及 SHA-256。它不产生 Finding，不自动转换成 hit/pass/skipped，也不写入正式报告。

## 接口与页面

| 接口 | 作用 |
| --- | --- |
| GET `/api/knowledge/schema` | 查询实际八类字段、关系配对、三态值 |
| GET `/api/knowledge/graph` | 查看持久化公共定义；指定 audit_id 时查看该审计的冻结证据图 |
| POST `/api/knowledge/candidates` | 平台管理员按八类分组导入候选 |
| POST `/api/knowledge/policies/{policy_id}/verify` | 平台管理员明确核对发布机关、效力、有效期和所选条款，记录审核日志；不自动批准规则 |
| POST `/api/knowledge/clauses/{clause_id}/extract` | 平台管理员调用 knowledge 用途模型提取单条款候选 |
| POST `/api/knowledge/rules/{rule_id}/approve` | 检查来源和口径后明确审核，保存当前责任人 |
| POST `/api/knowledge/rules/{rule_id}/preview` | 平台管理员提交明确事实做手动条件试算，返回 `formal_finding=false` |

图谱页面补充政策、原文条款、适用概念、条件和例外的展示，详情显示版本、复核、单位、有效期及原文位置；关系显示中文业务含义。候选维护和审核目前通过接口完成，尚无完整的人工编审工作台。

已有原文清单可通过 `policy_graph.import_corpus(db, manifest_path, document_ids, originals_dir)` 选择导入：逐一核对原件与提取文本的 SHA-256，将原件按哈希保留到指定目录，识别条款并记录原文行号。所有政策保持 `unverified`，已分条条款保持 `parsed`，无法可靠分条则完整保留正文并标 `needs_review`；缺少发布机关时明确“待核实”。不因原文下载成功就判定政策有效或适用。

## 本地验收与剩余边界

验收使用隔离测试数据库，没有迁移正式业务库或改动原共享工作区。

2026-10-15 最终回归：160 项测试全部通过，其中图谱专项 21 项；依赖、Ruff、三组前端检查及 Git 差异检查通过。

- 自动测试覆盖建库/重复迁移、八类对象、引用与组合、精确金额边界、三态逻辑、例外、审批、版本快照、来源留存、权限、重启，以及写操作与日志的原子回滚。
- 用原有 Excel 生成与解析流程验证三类材料到 Metric 的取数，包括本期列来源适配和发票计数。
- 使用已有来源清单的 `VAT-LAW-2024` 原件验证真实语料入库：1 份政策、38 条原文，原件留存且效力仍标待核实。此项没有重新联网核验政策效力。
- 本地真实浏览器验证登录、图谱加载、政策搜索、条件节点、内部参数标识和来源关联；AI 在该验收实例关闭。
- AI 提取的协议、来源约束与候选入库使用模拟模型响应测试；本轮没有真实 DeepSeek 候选提取验收。

后续仍须人工确定首批真实增值税检测项目、阈值和主体口径，配置真实表单指标，完成政策/条款专业复核，再接入正式核验与报告；本轮不把这些业务工作计为完成。

以上是八表 Schema 阶段记录。后续混合检索、材料包与真实 DS 联调的实现、验收及剩余边界见 [知识图谱混合检索与材料包](知识图谱混合检索与材料包.md)。
